## FOLLOWUP-SEARCH-001：额外联网搜索服务配置与最小接入

**状态：已由用户明确要求纳入后续开发计划；尚未实现，不在本次验证入口修复中顺带开通。** 本条来自 2026-09-22 真实试用对联网能力的需求，不依赖 Task 15/16、完整 Research Agent 或通用插件平台。

- 用户问题：使用 DeepSeek 教学/验证时需要真实检索资料，不能把官网功能或模型声称已搜索当成应用实际能力。
- 最小范围：独立搜索服务的选择、地址/必要凭据配置、启停、连接测试；教学模型可继续使用 DeepSeek。默认不自动搜索，先明确发送给搜索服务的查询内容及使用边界。
- 待确认：具体供应商、费用预算、允许出站的信息范围；“列入计划”不等于授权购买、读取既有凭据或向新增服务发送学习正文。
- 接入约束：搜索结果标注来源链接和实际检索状态/时间；只把实际执行的结果称为检索依据，不自动变为人类复核或学习掌握证据。失败、超时或未配置时明确降级，仍可保存学习与作答；不静默换服务。
- 验收：设置在页面可见且可关闭；Mock 测试覆盖启停/失败/不泄密；使用用户选择并配置的服务完成一次真实检索验收。不得用模型生成 URL 代替搜索成功；不扩展任意网页爬取、后台自主浏览或工具平台。
- 排期：当前验证阻塞修复与复试之后，作为独立待办先确认配置契约和供应商，再实施。后续交接必须保留本条状态，不能仅以“待选服务”省略实际开发任务。

### Task 15：综合成果与成果图

**覆盖**：`CAP-FUT-001`

**依赖**：Task 15A。

**工作内容**：

- 建立综合成果与可验证成果的显式关联。
- 复用已有成果身份、标准版本和证据引用。
- 不复制证据、不重置历史。
- 展示成果图和个人证据覆盖层。
- 保持成果图与计划树、路径图和对话分支的职责分离。
- AI 只能提出关系候选；用户确认后才写入正式关系。
- 综合成果不能仅因子成果部分支持而自动宣布成立。

**完成标准**：

- 用户可以创建综合成果、关联已有可验证成果、查看证据覆盖、调整关系并撤销调整；
- 关系和证据引用可追溯，版本、审计、权限和历史保留可测试；
- 不因补上综合成果改变既有事实；
- 图形只承载长期成果关系和证据覆盖，不演变为通用图数据库或无限可视化平台。

### Task 16：学习路径图

**覆盖**：`CAP-FUT-001`

**依赖**：Task 15。

**工作内容**：

- 建立长期路线节点、可追溯分支、起点变化和可恢复位置。
- 保持路径图只表达路线连续性，不承载普通任务、单次会话或每条消息。
- 用户确认后才改变当前主线。
- AI 可以建议切换或恢复，但不能自动写入。
- 起点变化、暂停分支、恢复位置和变更原因保留历史。

**完成标准**：

- 用户可以调整起点、创建分支、暂停方向、恢复历史位置并查看当时变更原因；
- 路径图、计划树、成果图和对话分支职责清晰；
- 主线变化、分支恢复、版本、审计、权限和撤销边界通过测试；
- 不把细碎消息和普通操作全部暴露为图节点。

### Task 17A：回归教练视图与自适应承诺窗口

**覆盖**：`CAP-FUT-001`、PRD V2 第 1.2、4.1、4.3、8.4 节和产品决策记录第 13 章

**依赖**：Task 16。

**工作内容**：

- 实现默认回归教练视图：用户回来时能看到当前位置、已有证据支持的成果、未知和缺口、下一步推荐及理由，并能进入下一步行动。
- 提供恢复原委托、选择其他行动或查看依据的入口。
- 推荐必须能追溯到状态、事件、证据和规则，不能只来自模型偏好。
- 未授权原文、摘要和引用不得进入视图或 Agent 上下文。
- 实现最小自适应承诺窗口：初期只承诺少量学习会话，随真实执行、证据和节奏信号逐步扩展；不输出虚假的长期精确排期。
- 推荐或窗口调整不得自动修改正式计划、目标、路径或长期状态。

**完成标准**：

- 用户中断后重新进入时，默认视图满足 PRD 1.2 核心承诺；
- 下一步推荐、理由、证据缺口和权限边界可测试；
- 自适应承诺窗口只基于真实信号，不伪装成精确预测；
- 用户选择、确认和恢复路径可审计。

### Task 17B：主动后台教练

**覆盖**：`CAP-FUT-001`

**依赖**：Task 17A。

**工作内容**：

- 实现低成本事件记录、当前 Agent 运行复用、会话边界批量判断和计划级复盘。
- 非阻塞信号进入候选队列，在自然停顿或会话结束呈现。
- 用户明确要求、当前工作无法继续或高影响变化时才即时提示。
- 正式创建、路线调整或长期状态变化仍需用户确认。
- 建立预算、冷却时间和用户开关。
- 不使用多个常驻 Agent 进程，不自动修改正式计划或长期状态。

**完成标准**：

- 主动提醒不频繁打断学习；
- 候选创建、提醒、确认、拒绝、忽略和撤销可审计；
- 成本控制和用户自主边界通过测试。

### Task 18：模型策略层级与运行配置冻结

**覆盖**：PRD V2 第 7.5 节

**依赖**：Task 17B。

**工作内容**：

- 实现全局、计划、任务、对话和单次运行的模型策略覆盖。
- 未设置字段继承上级；本次运行冻结实际配置并可追溯。
- 记录 Provider、模型、配置版本、来源和错误状态。
- 模型能力或更强模型不得扩大数据范围、工具权限或事实写入权。
- Nautilus 只能建议升级，不能未经确认自动切换 Provider、模型或策略。

**完成标准**：

- 策略覆盖、继承、冻结、追溯和不扩权均有测试；
- 用户可以查看并调整各层级策略。

### Task 19：人格 Profile 与学习模式最小闭环

**覆盖**：PRD V2 第 7.5 节

**依赖**：Task 18。

**工作内容**：

- 将人格 Profile 与学习模式分开建模：前者控制表达风格，后者是可执行教学协议。
- 实现最小内置人格和学习模式，不引入社区共享或市场。
- 学习模式不扩展模型能力、工具权限或事实写入权。
- 运行时记录当前人格、学习模式和实际配置来源。

**完成标准**：

- 人格、学习模式、模型策略和工具权限可独立变化；
- 学习模式作为协议执行，不是一句 Prompt；
- 不做社区人格、学习模式或知识包市场。

### Task 20：知识包与能力插件治理最小边界

**覆盖**：PRD V2 第 3.5、8.5 节

**依赖**：Task 19。

**工作内容**：

- 建立知识包版本、来源、适用范围、限制、争议和未知的审查模型。
- 建立能力插件的显式登记、权限、沙箱、预算、失败路径和审计边界。
- 知识包只声明领域数据，不包含任意执行代码。
- 能力插件由统一 Agent Runtime 装配和授权，不创建另一套运行模式。
- 不引入 Web Search、开放网络 Agent、社区市场或通用插件平台。

**完成标准**：

- 知识包和插件职责分离；
- 版本、来源、权限、审计和失败路径可测试；
- 包外 AI 推断只能作为候选假设，不能升级为事实或硬前置。

### Task 21：统一工作台与 PRD V2 整体验收

**覆盖**：PRD V2 第 4、7、8、10、11.6 节

**依赖**：Task 20。

**工作内容**：

- 整合目标、计划、模块、行动、委托、会话、产出、证据、成果、路径和教练入口。
- 默认工作台展示当前状态和下一步，而不是内部数据结构。
- 保持任务学习环境、复核、成果、路径和教练之间的连续用户旅程。
- 建立 PRD V2 整体验收记录，区分已实现、已验证、未实现和暂缓能力。
- 不把完成 Task 17 时的状态夸大为完整 PRD V2。

**完成标准**：

- 用户无需理解旧模型与新模型并存即可完成长期学习闭环；
- 权限、证据、版本、撤销、审计和隐私约束在整体验收中复测；
- 只有本任务通过后，才可另行评估是否达到完整 PRD V2 目标。
