## 1. 已确认与未确认

已确认：Windows、Android、iPhone、Mac安装应用；各设备独立保存资料/对话，其他设备关机后仍能使用；AI对话要求当前设备联网，不要求离线模型。第一版接受两端同时在线且应用打开、连接可建立时直接同步；不要求发送端关机后的异步交付。冲突的联网/资料设置由用户选择，两端新增对话内容保留。作者目前没有可用于验证的Mac和iPhone；Android测试手机已确认可用。

09-28已确认首片：先在同一Wi-Fi/局域网同步独立验证App全部文字资料和已保存对话；资料并发修改保留两版，由用户选择后续使用版本，历史引用不变。Key不进入同步，不导入原trial。随后确认：并发续问保留两条可切换分支；解除配对停止交换但保留双方已有内容，再连接须重新确认；首版输入临时配对码并双端确认名称后同步。外网辅助服务仍未授权；后续真实数据迁移仍需单次授权。

## 2. 代码核对结果

| 现有能力 | 可复用部分 | 必须适配的部分 |
| --- | --- | --- |
| React/Vite界面 | 两处对话、资料/版本/分支界面、现有用户流程 | `frontend/src/api.ts`依赖同源HTTP/Cookie/SSE；须有设备内调用适配，不只是打开电脑网页 |
| Python服务 | 领域规则、SQL结构、Provider协议、来源/版本及已验证行为 | `backend/requirements.txt`含原生依赖；`search_scripts.py`使用子进程；桌面服务不能按原启动方式搬到手机 |
| 本地数据 | `db.py`与`learning_storage.py`的事务/迁移经验、稳定对象ID | `main.py`打开两个相关SQLite库；不能复制单库就恢复完整业务，也不能互相覆盖整库 |
| 事件账本 | `core/events.py`与`evidence_events.py`的幂等、版本、回放契约 | 只覆盖部分领域，普通对话/资料等仍直接写表；两端可能从同一版本各自产生新事件，现有单链追加不等于分布式合并 |
| 身份与配置 | 当前归属校验、Provider配置语义 | `auth.py`是单库本地身份和浏览器会话；不等于独立设备配对。`credentials.py`本地加密不等于设备间密钥交换 |
| 彻底删除 | `managed_purge.py`、资料清除和受控恢复屏障 | 当前只管理本机/登记备份，尚无远端副本确认、删除传播或撤销设备处理 |

主Agent复核了API请求、双库启动、事件追加、资料写入、凭据和清除边界；一名Sol以medium/fresh context完成限定只读审查。没有读取trial私文/密钥、复制数据库或执行业务测试。现有核心逻辑可作为移植的行为基准，不承诺源码全部直接复用。

## 3. 客户端选择

**推荐验证Tauri 2 + 现有React界面 + 设备内业务核心。** Tauri官方覆盖四个平台并能沿用Web前端；业务核心长期应统一，不能让桌面和手机长期各维护一套不同语义。[Tauri平台与前端支持](https://v2.tauri.app/)

| 候选 | 取舍 | 当前建议 |
| --- | --- | --- |
| Tauri + React + 逐步移植的共享核心 | 复用界面、四平台共同方向；需要移植Python业务逻辑，成本实质存在 | 优先验证；Rust适合设备存储/网络及共享核心，具体边界以验证结果定 |
| 原生壳内嵌Python + React WebView | 最大限度保留Python逻辑；原生依赖、解释器集成、生命周期和搜索脚本都要适配 | 保留备选；不能仅因Python可嵌入便认定现有服务可原样运行 |
| Electron桌面 + Capacitor手机 | 可复用网页，但分成两套壳；仍需解决手机本地业务核心 | 不作为首选 |
| Flutter/原生重做界面 | 平台覆盖可行，但会扩大UI迁移，当前没有对应产品收益证据 | 不作为首选 |

Python官方说明手机端采用嵌入运行；iOS的第三方二进制依赖还有额外打包步骤，`subprocess`不支持Android/iOS。Tauri的shell插件在手机上也不提供桌面式子进程启动。因此，桌面打包Python作为附属进程不能作为统一四端方案。[Python iOS](https://docs.python.org/3/using/ios.html)、[Python Android](https://docs.python.org/3/using/android.html)、[subprocess支持范围](https://docs.python.org/3/library/subprocess.html)、[Tauri shell](https://v2.tauri.app/plugin/shell/)

SQLite仍可作为各设备本地存储；Tauri有覆盖四平台的SQL插件，但领域写入应经过业务核心，不给页面随意改业务表的接口。是否使用该插件或核心直接访问SQLite由验证决定。[Tauri SQL](https://v2.tauri.app/plugin/sql/)

iOS构建需要macOS/Xcode。现有工作环境为Windows/WSL，作者无Mac/iPhone；苹果端保持必交付目标，但当前只能评估兼容设计，不能宣称已构建/安装/真机通过。不购买云构建资源，不擅自注册付费账户。[Tauri构建前提](https://v2.tauri.app/start/prerequisites/)

## 4. 推荐的同步方式

每台设备拥有本地资料、记录、业务运行能力及自身设备密钥；AI请求由操作所在设备发起。设备之间通过认证加密连接交换业务对象的增量变更，不复制正在写入的SQLite文件。

同步记录至少需要稳定变更ID、来源设备、对象ID、所依据的版本、依赖、结构版本及确认进度；断开后重传不重复导入。资料/消息/题目归属依赖齐全后才能呈现为可用；格式不兼容须说明升级需要，不能部分导入后当完整成功。收到已有AI回答仅保存，不重放Provider调用或重复计算帮助事实。

推荐优先做下列语义，不先引入全局CRDT：

- 不相关的新记录自动合并；同一回答之后两端各自续问，保留双方路径，不拼成虚假的先后对话。具体展现方式待确认。
- 设置按共同基础版本识别真正的并发修改；已明确确认由用户选择冲突的联网/资料设置，不能单靠设备时间决定谁覆盖谁。冲突解决本身也须能同步。
- 本机输入草稿、滚动位置、正在执行的请求不视为可随意覆盖的共享对象；草稿同步仍不在本片已确认范围。
- 已生成回答保持当时的资料/联网快照；修改当前设置不能追改历史。
- 现有要求明确密钥不进入同步数据：首版沿用每台设备本地配置Provider密钥。配置引用在该设备不可用时明确提示，不自动更换服务。

彻底删除沿用既有不可恢复目标：离线设备尚未处理时只能显示该设备待处理，不能宣称全设备已删除。同步先处理已知撤销/删除屏障，再处理旧内容，防止旧设备或旧备份复活私文。已断联或撤销的设备不能远程证明擦除，必须持续如实列出；“撤销访问”不等于“已删除其副本”。这些是现有删除要求的必要架构约束，不是放宽删除目标。具体离线衍生内容清除范围、设备丢失与重新配对流程需在数据契约中确认。

## 5. 连接与成本边界

**P2P不等于无需任何外部辅助服务。** WebRTC需要信令交换，并可能需要STUN/TURN；原生Rust候选iroh提供加密QUIC连接和穿透/中继，但默认预设会联系外部中继，不能未经确认直接启用。其设备公钥认证也不能代替应用层设备授权。[WebRTC连接](https://webrtc.org/getting-started/peer-connections)、[iroh连接与中继](https://docs.rs/iroh/latest/iroh/index.html)

建议把传输与业务合并分开，首先在可直接连接的网络验证。iroh可作为原生传输验证候选，WebRTC作为另一候选；均未选定或安装。外网可达性必须另行验证；失败时显示未同步并保留本地修改，不能无提示使用公共中继。是否接入辅助服务、费用及元数据范围需作者确认；不把免费公共服务可用性作为产品保证。无云数据仓库与无任何服务器资源成本是两个不同承诺。

应用打开应按可执行前台状态验收，不保证手机锁屏或后台长期持续同步；系统挂起后恢复应用时重新核对进度。已有接受的两端在线条件不能自动解释为接受特定后台行为，界面须明确当前是否正在同步。[Apple后台执行策略](https://developer.apple.com/documentation/BackgroundTasks/choosing-background-strategies-for-your-app)

## 6. 建议的实施顺序与验收

| 步骤 | 可检查的结果 | 通过条件 |
| --- | --- | --- |
| 1. 独立运行可行性验证 | Windows与Android最小客户端：本地示例资料/消息、设备内模型请求适配、保存后重开 | 关闭原电脑服务后，另一设备仍能查看和保存；请求确实由该设备发出。先用合成数据/模拟Provider，不碰真实trial |
| 2. 配对与双向同步 | 两个独立本地库配对、新增消息/资料、断线后恢复、设置冲突选择 | 无重传重复、无旧状态覆盖、双方新内容保留；拒绝未配对设备；删除屏障/备份恢复不复活私文 |
| 3. 完整学习旅程逐片迁移 | 普通学习室和题目讨论及其目标/提交/评估/帮助/资料依赖 | 每片可实际独立使用，逐项复用现有契约检查；不把聊天样例算完整学习产品 |
| 4. 苹果端验证与跨网验证 | 具备Mac/iPhone条件后构建、安装、独立使用及跨端同步；网络辅助方案另行选定 | 四平台实际互通，失联/挂起/重新连接有清晰状态；没有设备不能替代为已验收 |
| 5. 真实数据接续 | 提供可审阅的trial导入/校验/恢复方案，原有学习记录保真 | 获得针对该次真实迁移的授权后才执行；完成前保留现有trial正常使用 |

步骤1若无法证明手机端运行或成本明显超出预期，先复核嵌入Python备选，不推进大面积移植。Windows/Android先验证是基于当前资源的建议，不取消苹果平台。Android测试手机已确认可用。此验证不新增第二套真实trial，临时合成测试环境仅用于隔离验证。

A2私有资料外发边界已在原trial035启用；独立验证版尚无外部搜索，后续Rust学习流程迁移须在设备内兑现同样的执行授权边界，不能只保护电脑服务。原B–F范围不扩张、不删除。
