# Nautilus 当前产品开发路线

更新：2026-09-27。状态：**作者已确认，作为后续推进主线。**

本路线从当前原 trial 034 与既有已交付能力继续推进。详细需求语义仍以 PRD V2 和产品设计决定为准；当前实现与验证事实见开发状态。本文件只负责回答：**现在先做什么、之后按什么阶段推进、每个阶段做到什么程度可以结束。**

## 1. 路线原则

1. **先完成产品能力，再做整体 UI 改进。** 整体信息架构、布局、组件和视觉统一放在本轮功能范围收口后集中处理，避免前期反复重构。
2. **整体 UI 后置，不等于功能 UI 后置。** 每个功能仍必须随切片交付最低可用的界面、错误反馈、恢复入口和移动端必要可用性，不能用纯后端或静态入口冒充完成。
3. **按用户价值和真实依赖排序，不按旧 Task 编号排序。** 只有缺失对象、接口、权限、数据关系或运行契约才算硬依赖。
4. **已完成能力只作为基础，不重新开发。** 复用现有目标、计划、委托、会话、资料、证据、验证、完成、补练、回访、搜索、分支与清除能力。
5. **工程完成、trial 启用和真实使用价值分开。** Task13B 真实使用观察贯穿所有阶段，不由自动化测试替代。
6. **本轮范围有明确收口点。** 完成 A–E 的已确认范围后进入 F；以后新发现的平台、知识库、教学模式或插件需求进入后续版本，不自动延长本轮路线。

## 2. 总体阶段

| 阶段 | 核心问题 | 主要范围 | 阶段结束结果 |
| --- | --- | --- | --- |
| **A：个人日常版** | 能否在真实生活中稳定持续使用 | A1 跨浏览器/设备状态恢复；A2 私有资料外发执行边界；A3 本人手机安全远程续学 | 换设备、中断后仍能带着正确学习条件继续 |
| **B：资料长期复用与完整输入** | 资料能否长期保存、反复使用并准确回看 | 内部长期资料库、一个真实外部知识库完整连接、原附件保留、图片/OCR | 文本与图片资料进入统一、可追溯、可治理的资料链 |
| **C：可靠教学与模型控制** | 系统是否真正按学习过程教学，而非只连续聊天 | 完整教学运行时、完整模型策略层级 | 教学状态可执行、可恢复；模型和实际运行配置一致 |
| **D：长期学习推进** | 单次学习怎样连接为长期目标与下一步 | 成果图、路径图、自适应承诺窗口、后台教练 | 能解释能力依据、当前路线和下一步，并在合适时机提出调整 |
| **E：探索、个性化与能力扩展** | 如何增强探索、个人协作和扩展能力 | 完整分支剩余能力、人格、朗读、插件 | 探索可以整理收束，协作方式可调，扩展能力受控 |
| **F：整体 UI 改进** | 如何把已稳定能力统一成一个连贯产品 | 全站信息架构、导航、布局、组件、视觉与跨端体验 | 功能不再像逐项添加的模块，主要旅程清晰一致 |

## 3. A：个人日常版

A1–A3 共同定义“个人日常版”。三项完成后，本阶段结束，不继续往阶段 A 塞入其他功能。

### A1. 跨浏览器 / 设备恢复当前学习状态

**09-27状态：代码与相关后端、双浏览器旅程、TSC/构建及034→035隔离升级检查通过；原trial仍034，等待本次备份/升级/启用授权。首次旧浏览器迁入确认、冲突读取最新后用户重新操作已由作者明确选择。实际证据与运行状态见开发状态。**

**用户结果：** 在另一个浏览器或设备打开已有学习时，恢复同一条明确学习路径和当前资料/联网条件，不需要重新猜测系统状态。

**必要范围：**
- 服务端保存当前对话/讨论的所选回答路径；
- 服务端保存当前资料版本选择、普通参考/严格范围及冲突策略覆盖；
- 服务端保存当前对话的联网选择覆盖；
- 浏览器本地状态降为缓存，不再是唯一事实来源；
- 已生成回答及幂等重试继续冻结原运行配置，不因当前选择变化改写历史；
- 引用对象失效时明确要求重新选择，不静默扩大资料范围、不静默更换搜索服务；
- 处理两个页面/设备的旧状态覆盖问题，采用最小版本检查，不扩展为实时协同编辑。

**依赖：** 复用现有回答版本、资料版本、搜索设置、身份及归属校验。没有云账号、同步数据库、离线编辑或完整路径图的硬依赖。

**结束条件：** 两个独立浏览器上下文可以恢复一致的回答路径、资料范围和联网覆盖；旧页面不会静默覆盖较新设置；普通学习室与题目讨论均成立。

**明确留后：** 未发送草稿的实时多端同步、离线编辑、多人协作、云同步。

### A2. 私有资料外发的执行层授权边界

**用户结果：** 打开联网不等于允许把私有资料发送给搜索服务；确需外发时可以看清接收方和具体内容再决定。

**必要范围：**
- 区分教学模型读取资料、知识来源读取和向外部搜索/工具发送信息；
- 模型生成的工具参数只是提案，不自动等于外发授权；
- 公共、明确安全范围的查询继续自动执行；
- 涉及私有内容、超出已授权范围或无法判断的外发请求暂停执行；
- 用户看到接收方和拟发送内容，可批准、拒绝或取消；
- 授权绑定具体接收方、具体内容和当前运行，不被换参数或后续运行复用；
- 外部函数工具与能实际约束参数的路径执行该边界；
- 原生搜索若无法观察/约束厂商内部请求，不宣称获得同等审查保证，并对无法兑现边界的私文请求明确限制。

**依赖：** 复用现有 Runtime、工具调用、搜索服务、资料身份和权限语义。不是通用插件平台的前置实现。

**结束条件：** 合成私文不能在未经授权时到达模拟外部服务；允许和拒绝都有清晰结果；普通公共搜索不被强制改成逐次审批。

### A3. 本人手机安全远程续学

**用户结果：** 作者本人使用手机流量或其他外网安全访问同一 trial 和同一数据，完成真实续学，不建立第二份数据库。

**必要范围：**
- 使用受控加密连接，不直接裸露当前 HTTP 服务到公网；
- 保留 Nautilus 应用层授权；
- 页面、API、SSE/流式输出使用一致的远程访问路径；
- 可以授权本人手机、拒绝未授权访问，并关闭远程入口/设备访问；
- 复用 A1 恢复学习路径、资料范围和联网覆盖；
- 断线后按服务端实际状态恢复，不盲目重新提交；
- 只做当前旅程必要的移动端局部可用性修复，不启动整体前端重构。

**依赖：** A1 是“正确续学”的依赖；A2 是个人日常版安全边界的一部分，但不是建立网络连接本身的技术前置。

**结束条件：** 电脑选择学习状态 → 手机流量访问并授权 → 恢复同一条件 → 继续学习并保存 → 中断后恢复 → 回电脑继续，这条真实旅程成立。

**明确留后：** Android 原生客户端、离线同步、云数据库迁移、跨设备后台同步。

## 4. B：资料长期复用与完整输入

本阶段把“内部资料、外部知识库、原附件、图片/OCR”放进同一资料主线，避免分别建设互不兼容的上传、知识库和 OCR 系统。

### B1. 内部长期资料库与原件基础

**用户结果：** 同一资料可以跨任务、跨对话反复使用，不必每次重新上传或粘贴。

**必要范围：**
- 在现有资料身份和版本基础上增加长期组织/复用入口；
- 对话引用的是明确资料版本；资料更新不改写旧回答的历史依据；
- 取消当前对话参考不等于删除长期资料；
- 新接收的原文件与提取文本建立明确关系，支持原件回看/下载；
- 旧版本若从未保存原文件，不补造原件；
- 新原件、提取文本和后续引用从首版进入清除、备份和恢复关系。

**依赖：** 复用现有资料版本、范围、清除、来源展示和回答快照；不要求 Embedding 或向量数据库先行。

**结束条件：** 一份资料可在两个不同学习场景显式选用；更新后仍能准确回看旧回答使用的版本和原件。

### B2. 一个真实外部知识库的完整连接

**用户结果：** 已在其他系统维护的资料可以直接用于 Nautilus 学习，不要求全部重新导入。

**必要范围：**
- 先选择一个作者真实使用的外部来源完成连接；
- 明确可读取库/目录/集合范围；
- 当前对话显式选择使用哪个知识库，不默认检索所有连接来源；
- 检索相关文档/片段，保留文档、片段、版本和来源定位；
- 可以回到外部原文；
- 权限撤销、来源删除、连接失败、版本变化均有明确行为；
- 区分断开连接、清除 Nautilus 保存副本和删除外部原库，不能混为一个动作；
- 默认只读，不因读取能力自动获得写回权限。

**依赖：** 共用 B1 的资料/引用/版本模型；若真实外部来源是当前主要资料来源，B1/B2 可以调整实施顺序，但共同契约不可省略。

**结束条件：** 从真实外部库完成一次学习并回看实际引用；授权失效后不继续读取，不把历史缓存冒充最新资料。

### B3. 图片 / OCR 与原附件统一链

**用户结果：** 截图、扫描页和含图片资料可以参与学习，并能核对识别结果与原件。

**必要范围：**
- 原文件/图片保留；
- OCR/解析结果作为派生内容，与原页或区域关联；
- 识别失败和不确定内容可见；
- 回答引用可以回到原件；
- OCR 文字不冒充原始文件内容；
- 图片理解与 OCR 分开：读出文字不等于理解图表/结构；
- 随切片补齐所需模型输入模态能力校验，不等待 C 阶段完整策略界面。

**结束条件：** 从图片/扫描资料进入学习、核对原件、保存产出、再次回看这一完整流程成立。

**阶段 B 收口：** 内部长期复用、一个真实外部知识库和图片/OCR/原件链均成立后结束。不以“还能再接更多平台”为由无限扩张本阶段。

## 5. C：可靠教学与模型控制

模型策略前移到教学阶段；人格不作为教学运行时前置。完整模型策略界面也不作为第一条教学协议的开工门。

### C1. 教学运行时的最小执行契约

先冻结可执行教学协议所需的运行状态：
- 当前教学模式/协议；
- 当前步骤和用户尝试；
- 已提供帮助与提示层级；
- 本轮允许工具、资料范围和模型运行快照；
- 模式切换、取消、刷新和恢复规则；
- 教学状态不越权修改正式计划、事实或掌握结论。

复用已有帮助记录和分步教学，不重复建立第二套记录。

### C2. 完整教学运行时

**用户结果：** Nautilus 能执行教学过程，而不是只靠每轮提示词要求模型“像老师一样回答”。

**必要范围：**
- 落实已确认的运行时教学协议；
- 苏格拉底模式按 H0–H4 或后续确认的等价状态机执行，不是一段 Prompt；
- 用户请求直接答案/完整讲解时可安全切换；
- 提示升级、模式切换、重试、刷新和跨会话恢复保持状态一致；
- 与正式验证、帮助条件和证据记录继续分离；
- 按既有规划补齐本轮确认的其他学习模式与切换行为，第一条协议成功不等于整个运行时完成。

**结束条件：** 一段有状态教学可以中断后恢复，模式和帮助事实可追溯，不因模型自由发挥丢失运行边界。

### C3. 完整模型策略层级

**用户结果：** 用户能理解实际使用哪个 Provider/模型/策略以及配置从哪里继承，并控制覆盖范围。

**必要范围：**
- 全局 → 计划 → 任务 → 对话 → 本次运行的继承/覆盖；
- 当前生效值及来源可见；
- 本次运行冻结 Provider、模型、配置和必要资源参数；
- 运行中的修改只影响之后的运行；
- 更强模型不扩大数据范围、工具权限或事实写入权；
- 不静默切换 Provider/模型；
- 复用搜索/对话已有的运行配置冻结，不重做已完成部分。

**结束条件：** 教学模式变化、模型策略变化和工具权限彼此独立；历史运行可说明实际采用的配置。

## 6. D：长期学习推进

本阶段不是“做两张图再做提醒”，而是把能力依据、路线和下一步连成长期推进逻辑。

### D1. 成果关系、成果图与证据覆盖

**用户结果：** 能看到长期要形成哪些能力、已有何种证据、哪些维度仍未知或矛盾。

**必要范围：**
- 建立综合成果与可验证成果的显式关系；
- 复用既有成果身份、标准版本和证据引用，不复制证据；
- 图中展示关系和个人证据覆盖；
- AI 只提出关系候选，用户确认后才改变正式关系；
- 综合成果不能因为子成果局部有支持就自动宣布成立；
- 按实际需要补齐领域知识包/标准治理的未完成部分，资料检索结果不能自动升级为正式标准或硬前置。

**结束条件：** 关系来源、版本、权限、撤销和证据归属可追溯；关系调整不丢失历史证据。

### D2. 路径图与自适应承诺窗口

**用户结果：** 能知道现在沿哪条路线前进、为什么走到这里、哪些历史方向可恢复，以及近期值得承诺什么。

**必要范围：**
- 路线节点、起点变化、暂停方向、历史分支和恢复位置；
- 当前主线改变必须经用户确认；
- 保留变更原因和历史；
- 路径图只表达长期路线，不承载每条消息和普通操作；
- 完成自适应承诺窗口：根据真实执行、证据和节奏信号调整近期少量学习会话，不制造虚假的长期精确排期；
- 相关计划组织/路线调整的既有未完成规划在此归口，不另散落成尾项。

**结束条件：** 改变路线后历史仍可解释；近期建议能说明依据且不静默修改正式计划。

### D3. 后台教练

**用户结果：** 系统在真正有价值的时机提醒和建议，而不是每条消息都打断。

**必要范围：**
- 低成本结构化事件记录；
- 复用当前 Agent 运行；
- 会话边界批量判断；
- 未处理候选、重复阻塞、回访到期等触发；
- 用户明确要求、无法继续或高影响决定才即时提示；
- 预算、冷却时间、用户开关；
- 建议可接受、拒绝、忽略、撤销并可审计；
- 正式计划、路线或长期状态变化仍需用户确认。

**结束条件：** 主动建议可追溯、可关闭、成本有界，拒绝后学习流程正常。

## 7. E：探索、个性化与能力扩展

### E1. 完整分支剩余能力

在现有两处独立分支和分支图基础上补剩余能力，不从头重建：
- 分支比较、整理和已确认需要的合并流程；
- 必要的关系调整；
- 原始路径、来源和历史继续保留；
- 合并或调整不能篡改旧消息、证据或来源归属。

**结束条件：** 用户能把探索分支整理为可用结论，同时保留原始路径。

### E2. 人格 Profile

**用户结果：** 可以改变 Nautilus 的表达和协作风格，而不影响事实与权限。

**必要范围：**
- 人格原始描述、结构化配置、预览、启停、版本和回滚；
- 人格只控制表达/协作风格；
- 不改变工具权限、资料权限、教学协议、模型能力和事实写入权；
- 与 C 阶段教学模式明确分离。

### E3. 朗读

**用户结果：** 当前回答可以可靠地播放，而不是只有一个入口。

**必要范围：**
- 播放、暂停、继续、停止；
- 当前回答/回答版本切换后的行为清楚；
- 离开页面、重新进入、不可用和失败状态清楚；
- 不因朗读改变回答、证据或帮助条件。

### E4. 插件扩展体系

**用户结果：** 具体外部能力可以在明确权限和审计边界下接入，而不是把 Nautilus 变成无边界 Agent 平台。

**必要范围：**
- 插件/能力登记、启停、权限、预算、失败路径和审计；
- 由统一 Runtime 装配和授权；
- 不允许插件扩大角色或数据权限；
- 复用已经存在的 Web Search、知识库连接、解析等具体能力，不为了“平台统一”重做；
- 知识包的数据治理与可执行插件治理继续分离。
