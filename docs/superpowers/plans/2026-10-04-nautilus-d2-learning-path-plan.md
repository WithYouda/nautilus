# D2 学习路径图与近期安排：实施计划草案

日期：2026-10-04。状态：**作者已要求在新对话按本计划执行；本计划列出的三项产品方案已获批准，业务实现尚未开始。** 第一步已形成[工程契约/校准规则表](../specs/2026-10-04-nautilus-d2-path-contract.md)和[可操作桌面/手机草图](../prototypes/d2-learning-path.html)，规则已获作者接受，具体交互/跨计划边界及生成中切换待答复后按第二步实施。D1既定工程范围及最新修正已启用，相关检查复用，真实学习效果继续观察。

依据：[当前路线D2](2026-09-27-nautilus-product-roadmap.md)、[PRD V2](../specs/2026-09-02-nautilus-prd-v2.md)第4、5、8、9、10节、[产品决定](../../progress/nautilus-product-design-decisions.md)第13、14.9–14.12、17.6节，以及[原实施计划](2026-09-05-nautilus-first-slice-implementation.md)Task16/17A的详细契约。原计划保留契约，不决定当前阶段顺序。

## 1. 要交付的用户结果

用户打开一个学习计划，能看清目前采用的路线、为何调整到这里、之前暂停了哪些方向，以及从哪里继续；能查看接下来少量学习安排，依据实际执行与反馈调整，而不丢失过去的记录和成果证据。

典型闭环：查看当前路线 → 确认接下来几次学习 → 从其中一项开始 → 保存产出与实际反馈 → 查看有依据的调整建议 → 本人确认后更新安排。需要换入口、调整范围或换方向时，旧路线和恢复位置仍可查看。

| 视图 | 负责回答的问题 |
| --- | --- |
| 计划任务与可选模块 | 要做哪些事情，如何组织 |
| D1成果图 | 要形成哪些能力，已有何种证据 |
| D2路径图 | 当前走哪条路线，为什么变化，哪里可以恢复 |
| 近期安排 | 接下来承诺哪几次学习，依据与投入范围是什么 |
| 对话分支图 | 某段讨论从哪里分出，保留了哪段对话来源 |

D2包含路径图与自适应近期安排两部分；第一条可用旅程可以提前启用，但不代替整个D2完成。

## 2. 已确认的要求

- 路径图表达有长期意义的路线节点、主线、起点变化、历史分支、暂停方向和恢复位置；普通任务、单次会话和每条消息不全部变成图节点。
- 当前主线只能经用户确认改变。起点变化默认产生新的分支或路线版本，保留时间、可选原因和旧路线；查看历史不等于重新采用。
- 支持换个入口、缩小/扩大范围、换个方向三种意图；保留历史尝试、原始产出和证据，不因为切换路线清零学习状态。
- 计划可以直接拥有任务，模块为可选、可嵌套的组织容器。模块和路线节点不直接保存“掌握度”，任务完成与能力获得支持继续分开。
- 初期只承诺1–3次学习会话；取得足够真实信号后可扩展至3–7次；节奏稳定后才展示一到两周的具体安排，远期保持粗粒度。
- 校准依据真实执行、投入、验证/反馈及节奏信号，不能仅凭经过若干天、打开过几次页面或完成数量自动升档。时间效率、学习效果和个人偏好分开解释。
- AI提出路线和安排草案，正式变更经本人确认；推荐需要来源和理由，缺失信息保留未知。拒绝建议、AI不可用或无合格标准不阻止继续学习和保存记录。
- 复用既有成果、任务、委托、会话、对话位置和证据身份；权限、版本、撤销、内容清除与恢复保护沿既有边界执行。

## 3. 已核实的基础与缺口

| 已有代码基础 | D2复用与需补齐的部分 |
| --- | --- |
| `021_learning_guided_setup.sql`已有plan/module/action_link；`learning_service.py`读取模块 | 模块目前只有结构储备，没有创建、编辑、移动、排序的完整命令/API/UI；当前任务仍平铺。补齐最小组织能力，保持任务ID与历史归属可追溯 |
| `learning_setup.py`及Core支持一个任务的草案、确认和在原计划添加下一步 | 复用创建与确认流程；多项近期安排、持久草案及变更理由需要新契约，不能把单步草案当成承诺窗口 |
| `continuity.py`与`ReturnReviewCard.tsx`支持当前任务、续学、切换、停止及下一步理由 | 执行位置目前从当前/最近会话和委托推算，不是已确认主线。新增明确路线位置与决定引用，避免新增最近记录就改变路线 |
| `learning_position.py`、C1/C2保存回答版本内的教学位置、尝试、帮助与反馈 | 在路线节点中链接原记录；不复制对话正文，不把某条回答的进展注记当成长期路线指针 |
| `027_learning_continuity.sql`已有返回卡、选择和执行事件 | 复用真实操作来源；补路线身份、主线版本、起点/分支变更及用户可回看的理由，普通任务切换不自动生成路线分叉 |
| 委托有`time_budget_minutes`，会话有开始/结束时间，已有正式证据和回访结果 | 用户投入预算不等于任务预计耗时，会话跨度不等于有效投入；需补可核对的时长/节奏反馈和校准规则，缺失历史不补造 |
| `LearningPlans.tsx`、首页返回卡与D1画布交互已可用 | 在现有计划和首页接入；图的移动/缩放、选择与详情交互可复用，路线语义单独实现 |

旧`plans.py`/`PlanEditor.tsx`仍使用`subject→topic→task`和旧计时模型；D2不重新接入旧固定层级，也不把其`actual_minutes`直接视为新学习域的真实投入。

当前学习库为042。需要新存储时使用后续新增迁移，不改既有迁移；具体表名、API和编号在工程契约中确定。

## 4. 本轮批准的产品方案

### 4.1 入口和范围

推荐先按**计划管理路线**：每个计划保留一条当前主线及历史分支，切换计划不覆盖其他计划的主线。计划可没有目标，不要求先创建综合成果；同一成果可以被不同计划引用。

在现有“学习计划”的计划详情增加“路径图”和“近期安排”入口，首页返回卡仍负责继续当前学习，并可回到对应路线。长期路线、模块组织和近期安排在同一个计划上下文中联动。

目标级跨计划总路径是另一种可能范围，会增加多计划主线、冲突和恢复契约。本计划采用计划内方案，跨计划总图不在实施时自行加入；作者本轮要求按计划执行，已批准这一范围。

### 4.2 图形与详情

默认展示真正的路线画布：当前主线突出显示，暂停分支保留位置，候选方向与已采用路线明显区分。节点只显示简短名称、路线状态和当前位置；任务完成和证据支持使用各自的标记，不共用一个“已掌握”颜色。

推荐的桌面结构：

```text
计划名称                         [调整方向] [近期安排]

                 路径画布                         选择后打开的详情
  阶段/起点 ── 当前阶段 ── 后续阶段                当前节点
       └──── 暂停方向                              关联任务、成果
                 ··· 尚未采用的候选方向             变更理由、历史

  [缩小] [放大] [全图]           下一次：已确认的任务  [开始/继续]
```

线条表达真实的路线衔接或分叉，不能把成果“前置关系”直接画成已选路线，也不凭时间顺序猜造旧分支。缩放、平移和回到当前位置可直接操作。右侧对象名称与对应节点一致；“查看记录”“查看成果依据”“路线变更详情”分开提供，避免再次把整句关系当作另一对象名称。

手机保留空间图，缩放/全图入口首屏可见；点节点打开可关闭的详情抽屉，任务和近期安排在抽屉中按需展开。不得只检查窄屏不溢出，还要实际检查节点可读、选中/定位、分支恢复和嵌套弹窗。

### 4.3 起点变化与历史恢复

| 用户动作 | 推荐行为 |
| --- | --- |
| 换个入口 | 保留原方向及成果引用，预览新的起步节点/任务，确认后保存新的路线决定 |
| 调整范围 | 展示新增、保留与暂不继续的部分；不批量完成或删除旧任务，不迁移旧证据 |
| 换个方向 | 原方向保留为可查看/恢复的历史分支，确认后设置新主线与位置 |
| 从历史继续 | 先查看当时位置、记录和现在可用的任务，再确认恢复；已完成任务默认回看，需要新练习时创建明确的新安排，不重开已完成事实 |
| 撤销调整 | 通过新的决定恢复所选路线；保留撤销期间真实发生的学习，不倒退删除会话/产出/证据 |

推荐：切换主线的确认页列出受影响的近期安排和本计划正在进行的学习；确认切换时正常暂停受影响的会话、保留现场，再改变路线指针。新路线不自动开始会话或发送AI消息；其他计划不受影响。若目标已暂停/停止，则沿已有目标规则先重新开启。作者本轮要求按计划执行，已批准这个切换行为。

若新方向已经改变目标含义或计划归属，须在预览中明确沿用原计划还是另建计划，并保留原路线的来源入口；不以“换方向”静默重命名目标、跨计划搬迁旧任务或改写原意。具体跨计划转向边界在第一步契约中确认，不因此默认扩建总路径图。

### 4.4 近期安排与更新

界面用“近期安排”这个名称；默认只突出下一项，其余按需展开。每项包含所做任务、关联路线位置、可用的时间范围及简短理由；依据详情再显示来源、假设和未知。

安排项是尚待执行的承诺，不是提前创建的真实学习会话。开始时复用现有委托/会话流程；中断、分次继续、改期、跳过均保留实际记录，不能用未来安排数或打开次数充当学习次数。完成某项安排也不自动完成目标或宣布能力达成。

推荐先由用户点击“更新近期安排”触发分析；手动添加、调整顺序、缩短或暂不采用始终可用。AI只给变更预览和依据，确认后才保存新版本；已执行项保留历史，未执行项的保留/替换/延期可逐项核对。D2不运行后台定时AI或主动通知，相关能力属于D3。

### 4.5 自适应范围与规则准备

| 真实信号情况 | 推荐输出 |
| --- | --- |
| 初次使用、关键记录不足或方向刚改变 | 1–3次学习的短安排，说明主要未知 |
| 多次有效执行、可核对的投入与反馈足以支持近期判断 | 建议扩展至3–7次，展示扩展依据和变动，由用户确认 |
| 多轮安排与反馈显示节奏稳定，且用户提供了可用时间 | 建议一到两周的具体安排，仍保留时间范围与调整余地 |
| 反复超出预计、粒度不合适、反馈矛盾或用户表示负担过重 | 建议缩短/拆分/替换未执行部分，不把中断或跳过当成能力失败 |

这些范围及第一步的具体校准规则已经作者确认，执行见[工程契约规则表](../specs/2026-10-04-nautilus-d2-path-contract.md)。按各轴实际来源与情境覆盖解释未知、矛盾及回退，再实现依赖它的建议。不得仅按次数升档，也不把一个全局评分或AI自报置信度当作已校准。

推荐由Core规则确定信号是否可用和建议范围，AI负责提出有依据的草案与解释；模型不能绕过规则自行宣布节奏稳定。人工调整安排与系统校准结论分开保存。

规则设计必须区分：用户给的时间预算、任务预计耗时范围、可核对的实际投入、会话自然跨度。推荐在既有暂停/完成流程中提供可选投入与节奏反馈，允许纠正并标来源，不增加强制填写步骤；没有可靠投入数据时保持未知，不推算精确效率。

验证、帮助、变式与迁移各保留实际来源和证明范围，不额外要求每项任务先做AI考试。演示/测试数据不作为真实校准信号；规则表需明确其识别和旧历史准入方式，不能只靠任务名称猜测。用户自行安排更远内容属于个人安排，不因此升级系统估计的可信度。

## 5. 实施顺序与逐步验收

### 第一步：确认工程契约和具体草图

- 根据第7节反馈确定路线归属、切换影响和更新触发；明确节点/边/路线版本/当前位置/恢复位置及安排项的职责。
- 提交校准规则表与桌面/手机可审阅草图，包含主线＋暂停分支＋候选方向＋历史恢复＋近期安排的完整例子。
- 明确与既有Core、执行位置、教学位置、成果身份、时间记录和内容清除的映射；列清依赖行为的未决项。

**验收：** 作者能在草图上指出如何从当前位置继续、如何换方向、如何查看旧依据，以及确认近期安排会改变什么。未决契约不交给实现Agent自行猜测。

### 第二步：计划组织与手动路线形成可用首片

- 补齐可选模块的创建、改名、嵌套、移动和排序，以及计划内任务归属/排序；不要求简单计划先建模块。
- 用新命令/事件保存组织变化，保持任务、委托与成果ID；不改变旧setup事件只接受空module_id的历史契约。
- 从已有计划选择任务/成果形成可编辑路线草案，用户确认后建立主线和当前位置；旧数据没有路线历史时如实从本次开始记录，不生成假的过去。
- 同时交付可交互路径图、节点详情及开始/继续/回看入口，不等所有后台表完成后才补界面。

**验收：** 一个既有计划能形成路径、组织已有任务并从节点继续学习；保存、刷新和回看身份一致，其他计划与证据不变。

### 第三步：起点、分支、暂停、恢复与撤销

- 完成第4.3节三类调整、主线确认、暂停分支、从历史继续及变更理由回看。
- 路线当前位置与实际执行位置可解释；普通切换任务不自动产生长期路线分叉。
- 主线变化与受影响近期安排使用一致的变更预览；并发旧页面须重新核对，不能覆盖后来的决定。

**验收：** 换方向后仍可回到旧记录和位置；恢复或撤销不丢失新旧学习事实，目标关闭与单运行会话约束保持。

### 第四步：近期安排的手动/AI完整闭环

- 提供初期1–3次安排的草案、编辑、确认、开始、继续、完成关联与修订历史；复用单任务确认和已有返回卡。
- AI按用户选定计划的已采用路线、关联任务与允许读取的真实摘要提出下一步近期安排草案，保留来源、理由和不确定处；不默认读取所有历史正文。
- 复用C3配置冻结和现有权限边界；按真实输出规模设置并冻结资源预算，区分连接、截断、结构、过期等失败，当前正式安排不因失败丢失。

**验收：** 用户能比较安排变更并接受/调整/拒绝；确认才改正式安排，AI不可用仍可手动继续，刷新/取消/重试不重复创建任务。

### 第五步：依据真实信号调整窗口

- 按已审阅规则接入执行、有效投入、实际反馈、证据及节奏信号；补齐必要的可选反馈与来源，而非重建一套学习档案。
- 实现保守保持、扩展至3–7次、稳定后一到两周，以及信号不足/变差时的缩短建议。
- 展示本次建议使用了哪些记录、为何改变、哪些仍未知；规则与输入版本可追溯，数据清除或来源变化使旧建议失效。

**验收：** 对不足、稳定、矛盾和方向变化的隔离样例给出可解释的不同建议；时间经过、演示记录和单次成功不能触发虚假的稳定判断。本人真实体验另行记录。

### 第六步：完整旅程检查、启用与本人试用

- 聚焦“看路线→确认近期安排→开始/中断/恢复→换入口或方向→回看/恢复旧分支→根据反馈调整”的完整旅程，独立检查桌面与手机的实际图形效果。
- 核对新组织/路线/安排事件回放、版本冲突、跨owner访问、来源清除/备份/恢复屏障与AI迟到结果；路线或模块调整不复制/重置证据。
- 若需迁移，按常设授权使用正式工具升级同一原trial，停写、自动前后备份和数据/完整性检查后启用；不把历史迁移批准重复当作待审批项。
- 保留已有检查结果，只重测改动影响的旅程和数据边界。每个可用切片通过检查后即可本地提交和启用，完整D2按下一节收口。

## 6. D2完成条件与范围边界

1. 路径图能表达当前主线、起点变化、历史/暂停分支、候选方向与恢复位置，并能进入实际任务、记录和成果依据。
