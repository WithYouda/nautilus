# FOLLOWUP-DELAYED-001：窄领域延迟回访标准与实施切片

状态：2026-09-26 产品负责人明确批准本标准的领域、题组、评分和解释口径。独立标准已冻结，工程实现与相关检查已完成；已按作者本次另行授权在原trial032启用，未改变已有成果状态。现有已确认范围见 PRD V2 当前补充及产品决定第4.4节。

## 1. 已批准的首版范围

采用 **Python 正则字符类与有限量词的匹配判断**，作为独立的窄领域回访标准 `python-regex-match-followup-v1`，不改写已批准的 `python-regex-basics-v1`，也不把它冒充原标准的兼容升级。

可观察行为：给出一个固定的 Python 正则表达式与若干短字符串，用户判断每个字符串是否被 `re.fullmatch(pattern, text)` 整体匹配。只检查 ASCII 字符范围、字面量和有限数量重复；不要求编写或执行用户代码，不检查一般正则设计、概念解释、性能、泛化或迁移能力。

选择理由：与现有正则标准的领域相邻，评分可直接对照固定输入的确定性结果，避免让同一AI同时出题、打分并宣布保持能力。代价是覆盖范围很窄，不能用于其他学习主题；后续扩展必须增加对应标准。

规范来源：[Python 官方 re 文档](https://docs.python.org/3/library/re.html)，具体依据为字符集合、`{m,n}`、`{m}` 和 `re.fullmatch`。官方文档支持匹配语义，不为本产品的间隔、题量或学习效果背书。题库、评分规则和执行器均需固定版本及内容摘要。

## 2. 已批准题目与评分

每轮两组、共8个判断；显示全部要求及输入，不隐藏额外评分门槛。作答前不返回答案；未选项不能偷偷按错误或正确处理，用户可退出并保留草稿。

| 轮次 | 表达式 | 字符串与标准结果 |
| --- | --- | --- |
| 初次记录 A1 | `[A-Z]{2}[0-9]{2}` | `AB12` 是；`A12` 否；`Ab12` 否；`AB123` 否 |
| 初次记录 A2 | `x[0-9]{1,2}` | `x7` 是；`x42` 是；`x` 否；`x123` 否 |
| 回访 B1 | `[A-Z]{2}[0-9]{2}` | `CD34` 是；`C34` 否；`Cd34` 否；`CD345` 否 |
| 回访 B2 | `x[0-9]{1,2}` | `x8` 是；`x56` 是；`x` 否；`x456` 否 |

保存全部作答及实际逐项检查结果，不只保存总分。8/8表示“本组匹配判断全部正确”；其余显示具体不同结果，不扩写为学习失败。初次和回访分别报告，不能以后一次覆盖前一次。相同错误结构和少量输入变化只构成同范围再测，**不是迁移题**。

初次记录用于建立同一标准下的比较起点，已有AI评分或正则v1的单样例匹配不能自动替代。只有用户主动选择这个回访方向才做初次记录，不给一般补练增加考试门槛。

## 3. 时间与条件

- 初次作答保存后，用户可选择是否安排及当地日期/时间，默认建议3天后，可调整。服务端保存UTC时间和实际时区；不从日历日期推断时长。
- 最小比较间隔为24小时，从初次作答提交至回访首次作答提交计算。这是首版操作性边界，不是科学最优间隔、记忆模型或稳定掌握阈值；跨午夜但不足24小时不能称为符合本标准的延迟再测。
- 到期前可以查看安排、改期或跳过；到期后增加开始入口。逾期不作能力失败，不产生负面证据，不自动追加下一条。
- 展示两次提交的实际时间和间隔；已开始后提交较晚按真实提交时间计算，不能用计划时间或开始时间替代。
- 单列用户报告（未使用帮助／使用了帮助／不确定）与产品可观察记录（本回访内提示、原答案或反馈展示）。外部资料、其他设备、其他对话和间隔内再学习不可全面观测，始终保留未知；无记录不证明独立完成。
- 回访首次作答前不主动展示初次答案及反馈。用户仍可选择查看，记录发生时间和具体版本，随后保存的答案明确带该帮助条件；后来查看不修改旧答案。
- 只有两次均全部正确、实际间隔达到下限且帮助条件适用时，描述为“在记录的间隔与条件下，两次同范围匹配判断均正确”。自报无帮助仍注明未独立核实，不能推导“独立延迟保持已获证实”。有帮助或未知时展示相应条件下的结果。
- 本标准不产生迁移结论、不宣称稳定掌握；不会补齐旧v1的任何证据配方，不重开已完成委托，不自动修改计划。

## 4. 最小用户流程与实现边界

在正则相关成果的依据回看中提供窄领域回访入口，明确题型和范围，由用户选择关联；后端核实成果/委托归属，不能仅凭标题猜测关联。旧标准只作为来源引用保留，新标准独立标记；没有适用关系的其他主题不显示通用回访能力。

流程：选择窄领域回访 → 保存初次作答 → 展示本次确定性检查 → 选择安排时间 → 首页应用内到期入口 → 开始／改期／跳过 → 保存新作答 → 检查结果 → 单成果回看。首页回访接口单独加载、失败可重试，不阻断核心学习入口。

- 保存与检查分别记录；检查失败仍可读原答案并重试。固定题目使用服务端确定性执行器，无真实Provider依赖。
- 固定题库下，同一所有者、成果、标准只保留一组初次/回访记录，即使已跳过、完成或清除，也不另建一组冒充新样本。幂等重试返回原对象，改期保留历史，开始与跳过不重复产生学习事实。
- 原有 `learning_evidence_follow_up` 只绑定证据主张，不能强造一条主张来获得安排ID。优先复用其日期/到期查询和回访呈现方式；独立初次/回访结果需要自己的明确关联。
- 现有 `learning_practice` 的来源为AI逐题反馈，不能将固定题目冒充AI补练。复用先存作答、版本快照和成果回看的契约，新增最少的回访/作答记录；迁移032新增回访、作答和查看三表，真实trial迁移需本次单独授权。
- 安排引用原成果、委托、原始依据及版本；结果引用初次记录、新作答、标准版本和执行器版本。事实、用户报告、条件观察、评分和能力解释分开，不复制无关聊天。
- 新内容从首版接入选定对象清除、来源删除联动、受管理备份清除、恢复屏障及迟到结果保护。隐藏来源时不可借回访读取原文。清除不得擦掉无关成果或已有执行完成事实。
- 当前固定题库两轮用于首版；看到答案后的重答是带反馈再试，不能恢复为首次独立样本，也不把重复题库作为无限次保持测量。

## 5. 有限验收与交付顺序

1. 作者已批准领域、题组、评分与解释边界；冻结独立标准及审批来源，不覆盖已批准v1。
2. 完成日期/时区、到期、开始/改期/跳过、去重与保存/检查/回看流程；围绕这条旅程进行相关后端检查、一次完整浏览器验证和TSC/隔离构建。
3. 重点验证不足24小时、跨午夜、未知/有帮助、先失败后重试、换版本、来源隐藏/清除、备份/恢复屏障；不为列举数量运行无关全套。
4. 如需032迁移，先完成合成升级和旧记录一致性检查，再按现有边界请求原trial本次迁移授权。031的授权已经执行，不扩大为032授权。
5. 原trial启用后由作者真实跨日使用。工程验收不替代Task13B，尚无真实结果时保留未验收。

## 6. 本轮核查结果

当前正则v1只有语义分析、确定性匹配和独立复核三个维度，没有本标准的双次固定题组及时间条件。原回访表只有pending/completed/cancelled和可选due_at，界面未提供完整日期/开始/改期/跳过流程。补练已保存独立尝试及帮助快照，但以AI题目/反馈为来源；不能原封不动当作标准化再测。

本标准已获作者批准，但工程完成不代表已经证明学习效果。其他领域、正则编写/解释、迁移和自适应间隔均留待后续标准，不在此次批准范围内。

题目语义核查：在当前仓库Python运行时逐项执行上述16个 `re.fullmatch` 输入，全部与表中结果一致。该核对仅确认题组预期，未创建学习记录、调用Provider或验收学习效果。
