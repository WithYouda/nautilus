# 项目实践运行时首片

日期：2026-10-04。作者明确选择设置页项目实践、分享当前作品并按版本反馈、点“下一步”才推进的流程。遵循PRD V2及[产品决定9.4–9.5](../../progress/nautilus-product-design-decisions.md#94-学习模式)；实际检查与启用状态统一见[开发状态](../../progress/nautilus-development-status.md)。

## 已确认流程

- 在设置页选择“项目实践”，围绕用户想做的小作品明确作品目标与当前一步；信息不足先澄清，不提前排完所有步骤。
- 用户分享文字、代码或操作结果后，AI针对这一版给出反馈并等待。只有点击“下一步”才推进，也可跳过；该动作不表示完成确认。普通提问、求助、说懂了或仅说做完了不算实际作品。
- 用户可自然提出修改要求；新要求另存一版，旧要求及对应作品、反馈仍可回看。未明确要求修改时不能覆盖当前要求，引用或代码中的指令不获得修改权。
- 默认折叠的“实践记录”按步骤展示要求、原话和反馈，并允许纠正实际尝试识别。帮助与完整讲解随时可用；单次复述或变式活动结束后回到原项目当前步骤。
- 默认/当前路径覆盖、临时方式和已接受请求冻结沿既有规则。取消、截断或无效元数据保留原检查点及已生成的部分正文。

## 状态与来源

协议`teaching-v7`兼容v1–v6，新增持续方式`project`与动作`next_step`。传输沿[结构化输出契约](2026-10-03-nautilus-teaching-output.md)，同次提案新增可空`project`字段，其对象严格包含`goal / instruction / feedback / change_quote`，未用字段为null；其余教学模式的旧记录仍可读取，不增加识别或修复调用。

首次建立项目须逐字引用最终AI正文中的目标和当前完整要求，`step/attempt`为null。Runtime创建项目身份、当前步骤身份及来源范围；下一步只提供新要求并关联前一步，不能顺带改目标。修订须绑定本轮真实用户修改请求与新要求，可同时修订目标；Runtime要求明确的修改措辞，否定或被引用的请求不授权。表达不明确时保持原状态，用户可明确重述修改要求。

实际作品沿`attempt`引用本轮用户原文，`project.feedback`引用本轮对应反馈，绑定项目及当时步骤；反馈不同时更换要求或推进。检查点保存当前目标/要求、等待作品或已有反馈、最近观察及前一步/修订请求。历史记录保留每版要求和作品，不把旧作品追认到新要求下。引用均为Unicode码点范围；工具前的正文不能充当最终轮来源。

嵌套独立分支映射项目、目标、步骤、前一步、修订请求、作品、反馈和帮助来源；严格范围/资料清除沿现有依赖闭包，记录只保存来源与跨度，不复制私文。纠正只追加分类记录，不改原文或历史冻结条件。正式完成、验证和Core产出均不由这些观察派生。

## 首片边界

当前对话与题目讨论可以没有活动学习会话，因此不静默创建正式计划/会话，不把聊天实践记录冒充Core原始产出。现有正式产出保存、不可变修订、完成确认和进入验证流程独立保留；AI失败不会抹掉已接受的用户原话。普通观察进入正式验证仍需单独核清标准与帮助映射。

反馈只依据实际可见的文字、代码或结果，不声称已经运行代码、查看本地文件或验证作品。无新增执行工具、数据库表、迁移或依赖；不评分、不认定掌握、不按步骤数自动调整正式计划。合成真实模型检查与工程检查均不等于长期教学效果验收。
