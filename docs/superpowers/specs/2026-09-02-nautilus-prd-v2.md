## 1. 产品定义

### 1.1 定位

Nautilus 是面向**正在进行持续、深度、可验证学习的学习者**的长期学习协作者。

它帮助用户把以下几件经常脱节的事情连接起来：

```text
用户真正想达到的结果
    <-> 当前采用的学习路径
    <-> 现实中执行过的行动
    <-> 可追溯的学习产出与证据
    <-> 当前可信的学习状态
    <-> 下一步最值得做的行动
```

### 1.2 核心承诺

> 用户每次回来时，Nautilus 都能说明用户走到哪里、什么已经被证据支持、什么仍然未知，以及下一步最值得做什么。

### 1.3 服务对象与边界

Nautilus 不按考试、学科、职业身份或具体知识领域限制服务对象。考研、考公、考证、高校学习、自学编程、职业转型、专业深造和个人长期兴趣都可以成为使用场景。

但“任何学习者”不等于“所有教育需求”。核心服务对象必须具有持续学习意图，并且学习过程需要理解、实践、产出、验证、复盘或路线调整。一次性问答、轻量打卡、单纯背卡和机构教学管理不是产品核心承诺；它们最多作为入口或外围场景存在。

当前第一位真实用户是产品作者本人。自身长期使用可以用于发现连续性、状态可信度和实际价值问题，但不能直接等同于其他用户的市场验证。

### 1.4 不是什么

Nautilus 不是以下产品的简单相加：

- 只会讲题的 AI 导师；
- 只负责排期的 Todo 或项目管理器；
- 只负责重复记忆的背卡软件；
- 只保存聊天记录的聊天机器人；
- 只会一次性生成路线的计划生成器；
- 面向机构的课程、班级和教学管理系统；
- 没有证据边界的通用自主 Agent 平台。

## 2. 要解决的问题

长期学习的核心困难不是生成一份漂亮的计划，而是维护以下连续关系：

1. 用户目标可能模糊，且会随实践变化；
2. 真实可用时间、速度和阻塞点事先未知；
3. 任务完成不等于能力形成；
4. 重要证据可能在延迟回忆或迁移实践中才出现；
5. 中断后难以恢复学习上下文、路线和承诺；
6. AI 容易把事实、用户自报、观察和猜测混在一起；
7. 多个计划和学习方向会互相争夺时间、注意力和工具资源。

产品价值不是承诺一开始知道正确答案，而是让系统在不确定时保留未知，通过低成本行动获得信号，再逐步提高计划、节奏和学习判断的可信度。

## 3. 产品原则

### 3.1 可信状态优先

学习状态必须能追溯到原始产出、事实事件或可核验来源。AI 的流畅回答、模型置信度和无引用印象不能直接成为事实或掌握结论。

### 3.2 人在回路

AI 可以提出目标解释、路线、学习契约、证据主张和变更草案；Core/Runtime 负责校验，涉及正式计划、长期状态、权限、费用或高影响路线的变化必须经过用户确认或明确授权。

### 3.3 渐进披露

用户默认只面对当前必须做的一个决定。来源、假设、证据缺口、权限和内部状态可以按需展开，不把内部枚举或专业判断伪装成固定问卷。

### 3.4 可逆和可追溯

目标、路线、契约、证据主张和用户决定都必须版本化或保留历史。调整起点、切换路线、质疑主张和撤销处理不能覆盖或删除原始学习历史；普通删除是可恢复的用户操作，彻底删除是经授权的不可逆例外，必须清除被删除内容并触发相关证据失效与状态重算，同时保留最小审计元数据。

### 3.5 跨领域但不泛化为无边界平台

产品语义和 Runtime 不依赖单一学科；领域知识包可以逐步扩展，但每个知识包必须声明来源、版本、适用范围、限制和未知。首个知识包采用窄领域示范，以验证关系、来源和证据链的可审查性。

## 4. 核心用户体验

### 4.1 两个主要交互场景

用户不需要理解内部多个 Agent。产品表面上主要保留两个场景：

1. **学习教练**：日常入口，跨计划恢复节奏、解释优先级、提醒风险、汇总状态和推荐下一步；
2. **任务学习环境**：进入具体学习行动后，进行讲解、答疑、练习、实验、产出和证据收集。

计划 Agent、Research Agent 和调度器在后台承担分析、检索和筛选职责，只在需要用户确认路线、来源冲突或高影响变化时显现。

### 4.2 终局用户主链

```text
表达学习意图
  -> 形成可逆目标理解
  -> 选择或探测学习起点
  -> 形成学习成果与路径
  -> 建立计划和可选学习模块
  -> 创建任务/学习行动
  -> 建立学习委托和版本化契约
  -> 开始学习会话
  -> 产生原始产出和事实事件
  -> 形成可追溯证据主张
  -> Core 派生学习状态
  -> 复核、回访、调整或切换下一步
```

这是一条可以循环往返的长期链路，不是一次性向导。回退、调整和路线切换创建新版本、分支或决定记录，不覆盖已经发生的事实。

### 4.3 日常学习闭环

```text
查看当前状态
  -> 理解今天最值得做什么以及为什么
  -> 用户选择或确认下一项
  -> 进入任务学习环境
  -> 进行学习、练习或实践
  -> 保存产出并记录会话
  -> 查看依据、缺口和待回访
  -> 继续、补强、暂停或调整路线
```

## 5. 领域模型

### 5.1 双轴模型

用户工作轴：

```text
计划 -> 学习模块（可选、可嵌套） -> 学习行动/任务 -> 学习委托 -> 学习会话
```

长期真相轴：

```text
学习意图 -> 学习成果 -> 证据覆盖 -> 学习状态 -> 延迟验证
```

计划和任务是现实工作的主要入口；学习成果是长期能力身份、证据归属和状态连续性的主索引。路径、任务支持关系、证据引用和版本负责连接两条轴，不能把两条轴做成互相重复的数据。

### 5.2 主要对象语义

| 对象 | 产品语义 |
| --- | --- |
| 目标 | 用户为什么学、最终想得到什么结果；一个目标可以关联多个计划 |
| 计划 | 当前采用的路线、时间安排和组织方式；计划结束不等于目标完成 |
| 学习模块 | 组织相关学习行动的可选容器，不直接代表掌握度 |
| 学习行动 | 用户要执行的具体工作节点，可以计时、产出和复盘；用户界面可以称为“任务” |
| 学习委托 | 围绕任务的一份长期工作单，定义本次要验证什么、边界和停止条件 |
| 学习会话 | 真实发生的一次学习过程；同一委托可以有多次会话 |
| 综合成果 | 用户希望整体达到的结果，可以组织多个可验证成果 |
| 可验证成果 | 可跨任务或计划复用的稳定能力身份，描述对象、行为和情境 |
| 达成标准版本 | 某次计划或委托对成果深度、质量、帮助条件和证据组合的要求 |
| 原始产出 | 用户实际提交的回答、代码、笔记、实验结果、作品或外部评审材料等不可篡改内容 |
| 事实事件 | 记录何时、由谁、通过哪个动作发生了什么；涉及产出时关联原始产出和学习会话，计时开始、会话结束等事件也独立存在 |
| 证据主张 | 说明某项原始依据对某成果、标准版本和能力维度的支持、反驳或不足 |
| 派生学习状态 | Core 根据当前可参与证据和标准计算的状态，不是用户或模型直接填写的分数 |
| 路径 | 表达长期主线、起点变化、暂停方向、历史分支和可恢复位置 |

任务、委托和会话不能混成一个实体；目标、成果和计划也不能互相冒充。

任务在领域语义上是可执行的学习行动，两种称呼指向同一个执行对象，不另建“学习行动”实体。界面可继续称为“任务”；具体代码、API 和事件名称留待工程规格统一，不构成旧模型兼容要求。

### 5.3 并行委托

同一任务可以拥有多个开放委托。当前焦点只是界面和推荐层的突出对象，不代表其他委托被暂停或失效；默认同一时间只运行一个实际学习会话。

委托的生命周期、当前焦点和学习会话必须分开建模。新委托依据独立学习承诺创建，而不是因为每次复习或每条消息都新建一份工作单。

## 6. 学习证据与状态

### 6.1 信息分层

长期系统必须区分：

```text
事实 Fact：系统或用户实际产生的事件
观察 Observation：基于具体依据的结构化观察
推断 Inference：对现状的解释或候选假设
决定 Decision：用户确认的计划、标准、授权或长期变化
```

AI 可以提交观察、证据主张、命令或变更草案，但不能绕过 Core 直接写入事实、正式计划或长期学习状态。

### 6.2 证据链

```text
原始产出（内容）+ 关联事实事件（发生上下文）
  -> 证据主张
    -> 学习成果 + 达成标准版本 + 支持维度
      -> 证据适用性
        -> 成果维度状态
```

原始产出与事实事件是两个不同对象：前者保存不可篡改的内容，后者记录何时、由谁、通过哪个学习会话和动作产生该产出。基于产出的证据主张必须同时引用具体原始产出及其关联事实事件；首片文本产出的候选主张均须满足这条引用链。

事实事件还可以独立记录计时、会话等活动；仅记录这类活动不需要人为创建产出。其他证据仍须引用其实际依据的事实事件或可核验外部来源，并遵守证明范围边界。证据主张记录发生时间、产生方式、资料/提示/工具、独立程度、验证方式、情境范围和隐私范围。

### 6.3 证据配方和状态

不同成果类型由版本化达成标准定义最低证据组合，不使用单一掌握分数、全局权重或模型置信度。即时解释、独立操作、测试结果、延迟回忆和迁移实践证明的是不同维度，不能互相无条件外推。

成果维度使用“主要状态 + 原因标签”，例如：未知、依据不足、初步支持、存在不同表现、待回访和支持。矛盾证据不做正负抵消；时间到期和标准变更触发 Core 重算，不改写原始记录。

### 6.4 证据主张审查

证据主张审查生命周期与状态贡献分离：

```text
候选 -> 已采纳 -> 被质疑 / 已撤销 / 已替代
```

机械事实和确定性验证可以自动采纳；带引用的 AI 语义主张默认作为候选观察，可形成初步支持，但不能仅凭模型判断形成稳定支持。用户质疑后立即移出当前状态计算，但保留原始产出、过去的派生结果和审计记录。

用户可以查看依据、采纳符合条件的主张、质疑、暂不处理或安排验证。采纳改变主张的审查状态，不直接升级成果状态；状态贡献仍由 Core 按达成标准和证据条件计算，用户认可不能把薄弱证据升级为稳定支持。

复核采用上下文触发的复核卡和全局待处理入口，不做逐条审批收件箱。同质、低风险、无冲突主张可以批量处理，但每条仍独立审计并可撤销。涉及冲突、长期状态、路线、委托、标准、权限、隐私或费用的事项必须明确提示。

## 7. Core、Runtime 与 Agent

### 7.1 Core

Nautilus Core 负责：

- 领域事实和状态转换；
- 计划、任务、委托和会话约束；
- 证据适用性与成果状态派生；
- 权限、审批、审计、回放和撤销；
- 对 Agent 提交的观察、证据和变更草案进行结构校验。

### 7.2 统一 Agent Runtime

所有 Agent 角色共享同一个完整 Runtime：

```text
统一 Agent Runtime
  + 当前角色契约
  + 当前数据范围
  + 显式工具授权
  + 沙箱与资源限制
  + 预算、超时、审批和审计
  = 本次完整 Agent 执行环境
```

学习教练、计划 Agent、任务 Agent 和 Research Agent 没有各自独立的运行模式；差异只来自角色职责、数据范围、工具授权和交接契约。学习模式（如苏格拉底、练习优先、费曼复述）是 Runtime 中可执行的教学协议，不是另一套 Agent 环境。

### 7.3 角色边界

| 角色 | 主要职责 | 关键限制 |
| --- | --- | --- |
| 学习教练 | 跨计划导航、恢复节奏、解释优先级、推荐下一步 | 不静默修改正式计划或长期状态 |
| 计划 Agent | 路线、成果关系、负载和排期分析 | 只提交草案，不绕过确认写入高影响变化 |
| 任务 Agent | 教学、答疑、练习、实践、产出和证据收集 | 不直接修改长期计划或把观察写成事实 |
| Research Agent | 来源核验、领域关系和临时知识分析 | 不直接升级正式知识包、成果图谱或计划 |
| 调度器 | 根据时间、状态、依赖和优先级筛选可行任务 | 不是 Agent，不承担教学和价值判断 |

### 7.4 全局 Agent 权限申请

全局 Agent 默认只读取跨计划的最小摘要、状态和证据引用，不能直接读取原始文本，也不能通过摘要或引用泄露未授权原文。上下文不足时，必须通过 Core 主动向用户申请最小读取权限，并说明目的、范围、内容粒度、时效和拒绝后的替代方案。

授权只扩大本次读取范围，不扩大写入、委托或事实确认权；授权受角色上限约束，不能自动转交给其他 Agent。批准、拒绝、过期和撤销都写入审计记录，用户拒绝后不得猜测未授权内容。

用户拒绝 Agent 读取权限后，仍可在自己有权访问的学习行动中继续学习、保存会话和原始产出；Agent 说明当前可见范围，并基于已授权信息继续，依赖未授权内容的分析保留为未完成。用户查看自己的产出不等于授权 Agent 读取。

### 7.5 人格、学习模式和模型策略

人格 Profile 决定表达风格，学习模式决定教学协议，模型策略决定能力层级和上下文/工具能力，思考强度只调整单次运行投入，工具权限由 Runtime 独立控制。选择更强模型不能扩大数据范围、工具权限或事实写入权。

模型策略由用户选择，可以在全局、计划、任务、单次对话和本次运行中逐级覆盖；未设置字段继承上级，本次运行冻结实际配置并可追溯。Nautilus 只能建议升级，不能未经确认自动切换 Provider、模型或策略。

## 8. 功能需求

### 8.1 目标与起点

- 用户可以直接表达目标，不要求先填写完整课程表或判断陌生领域路线；
- 系统通过结果示例、来源和低成本探测形成可逆目标假设；
- 用户每次只需做当前必要的一个决定，并可随时改道；
- 学习起点变化创建新版本或分支，保留历史尝试和证据；
- 没有稳定目标的计划可以先开始，之后再建立或调整关联。

### 8.2 路径、计划和行动

- 计划可以直接拥有任务，也可以使用可嵌套学习模块组织复杂行动；
- 首片直接使用新领域模型验证计划、学习行动、委托和会话；旧固定层级、旧入口和旧数据语义不进入新 Core；
- 计划树负责执行组织，成果图负责能力与证据，路径图负责路线连续性，对话分支负责讨论来源；
- AI 可以提出路线、重排、切换和恢复建议，高影响变化必须由用户确认；
- 任务完成、委托关闭和成果获得支持必须分别记录；
- 用户可以维护多个开放委托，但默认只运行一个实际学习会话。

### 8.3 会话、产出和证据

- 学习会话记录真实发生的时间、过程和结果；
- 用户可以提交文本、代码、笔记、推导、实验结果、作品或外部评审等产出；
- 先保存原始产出内容及其关联事实事件，具备合格标准时再由 Core/Agent 生成同时引用二者的证据主张；
- 证据主张必须指向成果、标准版本和支持维度；
- 用户可以查看依据、采纳符合条件的主张、质疑、要求复核、安排验证或暂不处理；采纳主张不等于直接升级成果状态。
- 复核和批量动作必须可撤销，每条主张独立审计。
- 学习会话和原始产出保存不依赖 AI 可用性；AI 超时、不可用、取消或输出不合格时，只记录分析运行失败，不生成空主张、伪造主张或学习状态。
- AI 分析失败不等同于“依据不足”；在有效分析完成前，系统应明确处于等待分析或分析失败状态。
- 用户可以稍后重试或主动请求重新分析；重试不得重复产生事实或重复计入同一批证据，失败记录和成功结果均需可审计。
- 用户可以查看原始产出并请求人工复核或补充验证；人工复核仍须引用原始依据并遵守 Core 的标准规则，不能仅凭用户动作直接升级学习状态。

### 8.4 学习教练

- 回到产品时可以看到当前走到哪里、已有依据、未知和下一步建议；
- 允许用户中断后恢复委托、会话和上下文；
- 跨计划汇总只展示最小必要信息；
- 当需要任务级私密内容时，主动申请窄范围权限；
- 主动提醒、候选委托和复盘在自然停顿、会话边界或高影响决策附近出现，不能逐消息打扰。

### 8.5 领域知识和能力

- 领域知识包是声明式、可审查、可版本化的数据，不包含任意执行代码；
- 知识包声明成果、关系、来源、适用范围、限制、争议和未知；
- 能力插件负责验证和执行，必须由统一 Runtime 装配和授权；
- 领域知识包不能把 AI 推断直接升级为硬前置或事实；
- 首个知识包采用窄领域示范，具体领域名称在工程实施时选择。

## 9. 数据与架构要求

### 9.1 混合事件账本

采用“关系型当前态 + 追加式事件账本”的混合持久化架构：

- 领域事件是历史事实、审计和回放依据；
- 关系型当前态是面向产品查询和操作的投影；
- 领域命令在同一事务中追加事件并更新投影；
- 进度、学习状态和回访队列可以依据事件和规则重新计算；
- 缓存、搜索索引和 AI 中间结果不能成为唯一数据源；
- 事件、原始产出和证据历史不得被普通更新覆盖。

首片事件账本至少遵守以下回放不变量：

- 每个事件有全局唯一标识；同一聚合内有单调递增的顺序号。首片不要求不同聚合之间共享单一全局顺序。
- 每个领域命令带幂等键。同一幂等键与相同请求只能产生一次事实并返回原结果；同一幂等键但请求内容不同必须拒绝。
- 事件追加和关系型当前态投影在同一事务内完成；任一方失败，另一方不能单独提交。
- 投影记录已处理到的事件位置，只能按预期顺序应用；重复事件可以幂等跳过，出现顺序缺口必须暂停并报告，不能静默跳过。
- 投影重建在隔离位置生成替代投影，校验通过后再原子切换；重建失败不得覆盖现有投影，并保留失败审计记录。
- 派生学习状态、回访队列和建议只能由事实事件、证据主张、达成标准和规则重新计算，不能反向成为原始事实来源。
- 事件版本不能静默改变含义；旧版本必须有显式升级器或明确的兼容读取规则，无法升级时必须阻止该投影重建并要求明确迁移。
- 回放必须校验事件数量、顺序、投影版本和关键领域约束，不能只以数据库事务成功作为重建成功。

这不是全量 Event Sourcing，也不是只记录操作日志。具体事件字段、投影表、重建工具和迁移策略属于架构工程规格。

### 9.2 版本、权限和隐私

- 目标、路径、成果标准、委托契约、证据主张和用户决定需要版本或历史关联；
- 原始产出不可篡改；事实纠正通过更正事件或新版本表达，不覆盖原内容；
- 普通删除是可恢复的软删除：内容从当前工作区隐藏，但原始内容和历史关联保留在受控回收范围内；若内容参与证据计算，立即移出当前状态并触发成果状态和回访队列重算，恢复时由 Core 按当前标准重新判断；
- 撤回是证据生命周期动作：不删除原始内容，只表示该产出暂不作为当前学习依据；依赖它的主张移出当前状态计算，内容和历史仍可查看，用户可以在未彻底删除且标准仍适用时明确恢复；
- 经授权的彻底删除清除或不可逆脱敏原始内容，不保留可恢复副本；彻底删除动作、授权主体、时间、影响范围和结果保留为不含私人内容的最小审计元数据；
- 彻底删除会使依赖该内容的证据主张立即失效并移出当前状态计算，触发相关成果状态和回访队列重算；缓存、搜索索引、临时文件和普通备份不得继续提供已删除内容；
- 每个对象有稳定 ID、来源和权限范围；
- 全局、计划、任务和独立对话的上下文范围必须显式保存；
- 读取授权、用户决定、状态转换、撤销和 Agent 交接必须可审计；
- API 密钥、Cookie、访问令牌和用户私人内容不能进入进度文档或普通日志。

事实纠正、普通删除、撤回和彻底删除都不能伪造新的学习事实：更正只追加可追溯版本，普通删除改变当前可见性并可恢复，撤回改变证据适用性，彻底删除清除内容。普通删除应是正常可用的用户操作；彻底删除前应向用户说明受影响的证据主张、成果状态和回访安排并要求明确确认。彻底删除完成后不得从普通备份、缓存或搜索索引恢复已删除内容，仍保留的审计元数据不得包含原始私人内容。

### 9.3 本地优先和安全

- 首阶段运行于 WSL2 本地 Web 环境，服务绑定 `0.0.0.0`，通过 WSL2 实际 IP 访问；
- SQLite 使用 WAL、外键和顺序迁移；
- AI 凭据与业务数据库分离并加密保存；
- AI 写入正式数据前生成预览并等待确认；
- 未授权资料和外部输入视为不可信内容，不能覆盖系统规则或直接触发工具；
- 不使用多个常驻 Agent 进程承载产品逻辑。

## 10. 用户界面要求

- 默认界面表现为一个连续的 Nautilus，不要求用户理解内部 Agent 名称；
- 日常优先显示计划、行动、状态和下一步，而不是内部数据结构；
- 内部状态使用自然语言表达，例如“已有一些依据”“还缺少独立验证”“存在不同表现”，不直接显示数据库枚举；
- 目标解释、复核卡和权限请求只展示当前必要信息，详情按需展开；
- 原始依据、隐私范围、来源和状态变化必须可追溯，但不能在无权限时泄露原文；
- 复核卡明确标出哪些依据因当前权限不足而不可见，以及由此形成的判断限制；在 Agent 参与的复核中，只有用户和当前 Agent 均有权限时才展开原文，权限提示不得夹带私密摘录；
- 计划树、成果图、路径图和对话分支各自承担明确职责，不互相替代；
- UI 不得用完成勾选或任务百分比伪装成能力掌握度。

## 11. 首个可验证纵切片

### 11.1 目标

验证 Nautilus 最核心的差异化闭环：用户完成一次真实学习行动后，系统能把原始产出转成可追溯的候选证据，并由 Core 派生出有边界的学习状态，而不是只保存聊天记录或完成勾选。首片采用两个连续验收门：先验证事实闭环，再验证证据闭环；第二门不得掩盖第一门的事实链问题。

### 11.2 范围

```text
创建或选择一个新领域学习行动
  -> 创建或确认学习委托
  -> 形成最小学习契约和一个可验证成果
  -> 检查是否存在可参与状态派生的达成标准版本
  -> 开始一次学习会话
  -> 用户提交一份文本产出
  -> 保存原始产出和事实事件
  -> 在有合格标准时，Agent 基于原文生成带引用的候选证据主张
  -> 在有合格标准时，Core 根据标准派生“依据不足/初步支持”等状态
  -> 展示复核卡、依据和缺口
  -> 用户可以查看依据、采纳符合条件的主张、质疑、安排验证或暂不处理
  -> 所有变化可审计、可撤销、可回放
```

### 11.2.1 首片标准准入与无标准降级

首个纵切片只有在存在**预先审核并版本化的窄领域达成标准包**时，才允许生成参与学习状态派生的证据主张。该标准版本至少声明来源、版本、能力维度、帮助条件和最低证据组合；AI 不得自行补齐、改写或临时创造达成标准。

用户提供的可追溯标准可以作为候选来源保存并进入后续审核，但在被纳入版本化标准包前，不得参与本首片的学习状态派生。“可追溯”不等于“已经通过领域审核”。

如果没有合格标准，系统仍必须允许创建学习会话、保存原始文本产出和事实事件；此路径不生成证据主张，也不派生“依据不足”“初步支持”或其他学习状态。用户界面应明确说明当前仅保存产出，待补充合格标准后再分析。该降级结果和标准缺失原因必须可审计，且不得通过空主张或模型猜测填补。

### 11.2.2 AI 分析失败路径

学习会话和原始文本产出必须先保存，不能因为 Agent 不可用、超时、被取消或返回不合格结构而阻塞事实闭环。上述情况只记录对应的分析运行失败和原因，不生成空主张、伪造主张或任何学习状态；分析失败也不等同于“依据不足”。

用户可以稍后重试或主动请求重新分析。重试必须幂等：不能重复产生原始事实，也不能让同一份有效证据被重复计入；失败尝试和成功结果都保留可审计记录。用户可以查看原始产出、请求人工复核或安排补充验证，但人工复核必须引用原始依据并继续遵守达成标准和 Core 的状态派生规则。

如果没有合格达成标准，不启动会改变学习状态的 AI 分析，继续使用“保存产出，待补充标准后再分析”的降级路径。

### 11.2.3 首片成果关联边界

- 首片要求至少有一项可验证成果，作为标准版本、证据主张和派生状态的目标；计划可以直接关联该成果，不要求先创建综合成果。
- 综合成果是终局的组织层，首片不强制创建、不自动补空对象，也不在没有跨成果证据时派生综合成果状态。若用户已有综合成果，可以作为上层关联保存，但首片验收仍以可验证成果及其能力维度为准。
- 目标是学习意图，不是证据状态的必要前置对象；没有稳定目标时可以开始首片。任务、委托和会话连接到可验证成果，不能把任务标题或综合成果名称直接当作证据目标。
- 后续建立综合成果与可验证成果的关系时，复用已有成果身份、标准版本和证据引用，不复制证据、不重置历史，也不因为补上综合成果而改变原有事实。
- 没有合格标准时，继续执行第 11.2.1 节的保存降级：可以保存目标、成果关联、会话、产出和事实事件，但不生成证据主张或学习状态。

### 11.3 首片不包含

- 附件上传和复杂文件解析；
- Web Search 或开放网络爬取；
- 代码执行沙箱和任意外部工具；
- 完整路径图、成果图和复杂可视化；
- 多 Agent 并行编排和主动后台巡航；
- 完整知识包市场、社区共享和跨设备同步；
- 把候选证据直接升级为稳定掌握。
- 旧 `learning_goal / subject / topic / task` 固定模型、旧任务/计划入口及其兼容映射、双写和适配层。

### 11.4 验收门

#### 11.4.1 验收门一：事实闭环

事实闭环必须先独立通过，范围包括委托、标准绑定、学习会话、文本产出、事实事件、关系型当前态投影和回放。至少满足：

1. 原始文本产出保存后不可被后续主张或投影覆盖、篡改；
2. 没有合格达成标准时，学习会话、原始产出和事实事件仍可保存，但不生成证据主张或学习状态；
3. 原始产出内容与事实事件分开保存；事实事件记录产生时间、主体、会话和动作等上下文；
4. 每个事件有唯一标识和聚合内顺序，每个领域命令的重试遵守幂等键规则；
5. 事件追加和当前态投影在同一事务内提交，失败时不能只提交其中一方；
6. 投影能在隔离位置重建并在校验通过后切换；重建失败不覆盖现有投影且有审计记录；
7. 跨身份访问、同一用户内部跨全局/计划/学习行动范围的越权读取和未授权写入均由 Core/Runtime 拒绝；不能只靠界面隐藏或 Prompt 约束，也不能以用户本人有权访问替代 Agent 授权；
8. 业务测试使用隔离数据库，默认 `data/` 不参与自动化验证；
9. 不启用 AI 分析时，用户仍能通过界面保存学习会话和原始文本产出，并在重新打开后读取已保存内容；事实闭环不得依赖证据闭环可用。

#### 11.4.2 验收门二：证据闭环

证据闭环只能建立在验收门一通过后，范围包括候选主张、状态派生、复核、质疑、撤销和证据相关回放。至少满足：

1. 每条候选主张都同时引用具体原始产出及其关联事实事件，二者必须对应同一次产出记录，并指向成果、标准版本和能力维度；
2. 无引用的 AI 印象不能进入证据链；
3. Core 能从当前可参与证据派生状态和原因标签；
4. 用户质疑后主张立即不参与当前状态计算，但历史、原始产出和审计记录保留；
5. 用户可以批量处理同质低风险主张，也可以展开单条依据、采纳符合条件的主张、撤销或暂不处理；用户动作不直接绕过 Core 升级成果状态；
6. 分别模拟 AI 超时、不可用、取消和输出不合格，用户仍能保存会话和产出，重新打开后内容可读；界面区分保存结果与分析结果，显示分析失败及原因，提供重试、请求人工复核或安排补充验证的入口。失败不生成主张或学习状态，也不显示为“依据不足”，失败原因可审计；
7. 重试不会重复产生事实或重复计入同一批证据，失败与成功运行均可追踪；
8. 状态、审查动作和撤销可以从事件与投影重建；回放校验事件顺序、投影版本和关键领域约束；
9. 事件版本变化有显式升级或明确拒绝重建的处理，不按新含义静默解释旧事件；
10. 事实纠正通过追加更正事件或新版本表达，不覆盖原始事实；普通删除和撤回按可恢复语义移出当前状态计算，彻底删除后相关证据主张立即失效，成果状态和回访队列完成重算，彻底删除内容不会从缓存、索引或普通备份恢复；
11. 全局 Agent 的默认上下文和读取结果只包含最小摘要、状态和证据引用，不含未授权原始文本；摘要和引用不能成为绕过权限的入口；
12. 当前分析需要超出权限的依据时，Agent 通过 Core 主动申请，用户能看到目的、范围、内容粒度、时效和拒绝后的替代方案。批准只开放约定读取范围，拒绝、过期或撤销后不得继续读取；批准、拒绝、过期和撤销均有审计记录，读取授权不扩大写入权；
13. 用户拒绝读取申请后仍能继续当前学习、保存会话和产出，并在重新打开后读取；Agent 基于已授权信息继续，说明未能完成的分析，不猜测未授权内容；
14. 复核卡明确展示依据的可见范围和权限限制；未经授权的原文或摘录不进入卡片或 Agent 上下文，用户可以暂不处理或安排验证，不能因缺少权限而被迫授权。

上述权限和失败路径必须通过 Core/Runtime 的隔离验证及可操作的用户流程共同验收，不能仅凭后端接口测试通过就视为用户体验完成。权限原则沿用第 7.4 节，AI 失败语义沿用第 11.2.2 节，不新增独立验收门。

### 11.4.3 新领域教学与验证增量验收（2026-09-16 同步确认）

保留既有事实门和证据门的历史验收；以下增量独立记录实现与验证状态：

- `CAP-VERIFY-001`：已有计划直接进入任务答疑/计时，不虚构新领域对象；自然语言目标只生成可编辑草案，确认后创建学习安排并进入学习室，准备好后自动发送首次教学提示。
- `CAP-VERIFY-002`：教学与考试式验证分离，由用户主动发起验证；支持 AI 场景/项目/简答/判断题及用户材料，拒绝填空/补全。标准答案本身不是用户能力证据。公开响应不含答案、隐藏评分依据或私密提交材料；来源 URL 只作 Provider 提供、未独立核验，不实现开放搜索。
- `CAP-VERIFY-003`：作答先保存再评估，提交历史不可被重试覆盖；幂等及并发不重复提交或让旧结果覆盖新回答。AI 失败可重试已保存提交；错误结构不公开，运行记录保留必要契约与模型快照。
- `CAP-VERIFY-004`：先评估、再核对停止条件、最后用户确认；确认绑定已保存结果，不重新评分。验证未通过、停止条件未满足或未确认均不得完成。多委托时只完成本次委托，其他开放委托使行动保持可继续；完成行动与成果证据支持分别表达。
- `CAP-VERIFY-005`：返回教学再进入验证可继续；重新打开能恢复已保存验证状态并重试或确认。真实学习会话与教学对话建立可校验归属，不因同属独立对话而恢复其他任务。未提交文本的跨刷新恢复不得用公开接口泄露私密材料。

优先补齐以上可靠性及 `INV-008` 启动迁移保护，再复用现有事实、证据和彻底删除链。无合格标准仍不得派生能力状态。最小完成后/返回时复核不依赖完整成果图、路径图；正式计划或目标的变化仍须用户确认。

### 11.5 首片成功指标与护栏

首片采用测量契约：先统一测量对象、分母、观察窗口、排除条件、来源事件和隐私保留边界，完成真实使用基线后再决定业务目标值。指标分为产品价值指标、硬性护栏和诊断指标，不能把诊断指标误当成价值目标。

产品价值指标至少包括：

- **中断后正确恢复委托比例**：用户中断后重新进入时，首次选择的委托与中断前实际委托一致，且不需要用户纠正；
- **复核到下一行动完成率**：用户查看或处理复核卡后，在约定观察窗口内安排并完成相关下一项学习行动；“暂不处理”、权限不足和等待验证单独统计；
- **证据可追溯率**：进入证据链的主张中，同时能追溯到具体原始产出、关联事实事件、成果和标准版本的比例。

以下是不可被其他指标抵消的硬性护栏：

- **无依据主张率**：没有有效引用、引用对象不匹配或违反标准准入的主张比例，必须为零；
- **AI 失败时产出保存成功率**：AI 超时、取消、不可用或输出不合格时，会话和原始产出仍成功保存且重新打开可读取，事实保存要求达到 100%；
- **事件重建一致性**：从事件重建的当前态与正常投影一致；顺序缺口、版本无法升级或重建失败必须单独暴露；
- **权限违规和隐私泄露次数**：越权读取、未授权写入、通过摘要或引用泄露原文均为零容忍事件。

用户质疑率、暂不处理率、无合格标准时的降级比例、分析失败重试率和人工复核请求率属于诊断指标。它们用于按主张类型、权限、情境和失败原因发现问题，不直接作为越低越好的优化目标。

首片先采集基线，不在缺少真实使用数据时设定业务目标值。任一硬性护栏未通过，都不能宣称首片成功，即使产品价值指标表现良好；具体事件字段、报表和采样实现属于后续工程规格。

测量口径如下，统计来源使用对应的事实、决定、分析运行及验证记录：

| 指标 | 分母或统计对象 | 成功条件与来源 |
| --- | --- | --- |
| 中断后正确恢复委托比例 | 有明确中断委托、用户选择继续该委托的恢复尝试，按尝试去重 | 首次恢复到原委托且无需纠正；关联中断、恢复、用户选择和纠正记录。主动切换委托单列，不视为恢复错误；意图不明时不猜测成功 |
| 复核到下一行动完成率 | 已查看或处理、存在相关下一行动且观察窗口届满的复核事项，按事项去重 | 窗口内已安排并完成相关行动，关联复核、安排和行动完成记录；行动完成不等于成果掌握。暂不处理、权限不足、等待验证和窗口未满分别报告 |
| 证据可追溯率 | 实际进入首片证据链的去重主张，包含候选主张 | 产出、对应事实事件、成果和标准版本均可解析且关联匹配；依据引用校验记录，不以模型自报为准 |
| 无依据主张率 | 与证据可追溯率相同的主张集合 | 无有效引用、关联不匹配或违反标准准入的主张数除以总数；进入证据链前被拒绝的 AI 输出归为校验失败，另报数量 |
| AI 失败时产出保存成功率 | 受四类 AI 失败影响的、用户已提交保存的会话和产出记录，重试按同一保存命令去重 | 保存成功且重新打开可读；依据保存结果、读取校验和分析失败记录。AI 分析取消不等于用户撤回产出保存 |
| 事件重建一致性 | 相同事件截止位置、规则及投影版本下应可完成的重建尝试 | 重建投影与正常投影的领域数据、数量、顺序和约束一致；重建失败或不一致计入失败，不能只统计成功切换。比较结果不能单独替代领域规则校验 |
| 权限违规和隐私泄露次数 | 统计期内已确认的违规访问、写入或内容泄露事件 | 各类违规分别计数；正确拒绝的越权尝试不算实际违规。依据 Core/Runtime 审计和隔离验证，不仅依赖用户投诉 |

测量还必须遵守：

- 每次报告声明统计时段、指标口径版本、分子/分母、单列情形和未知结果；观察窗口及中断判定在验证前由工程规格固定，不在看到结果后调整口径。零分母标为“无样本”，不能显示为 0% 或 100% 的通过结果。
- 质疑率按被用户查看的去重主张统计；暂不处理率按被查看的复核事项统计；无标准降级比例按进入标准检查的保存记录统计；重试率按失败的分析任务统计；人工复核请求率按已向用户呈现的可复核分析结果或失败事项统计。同一对象上的重复点击不重复计数，分母和对应来源记录必须随结果保留。
- 权限不足、等待验证等单列结果仍须报告数量，不能通过删去这些样本美化完成率。事实纠正、普通删除、撤回或彻底删除导致依据失效时，沿用第 9.2 节移出当前状态计算，并单列原因；历史统计不能成为继续保留私人内容的理由。
- 验收中的保存成功率 100% 适用于保存链路可工作的指定 AI 故障场景，四类失败分别验证；实际使用中的其他保存失败仍须记录，不能因不属于 AI 故障而隐藏。该验收不构成对所有硬件或存储故障的无限保证。
- 顺序缺口、损坏事件和无法升级版本的故障场景按第 9.1 节验证明确拒绝及现有投影保护；按预期安全拒绝不算重建成功，也不算投影不一致，须与正常重建场景分开报告。
- 指标只在已有功能范围内采集；恢复或后续行动样本尚未产生时标为未测，不为凑齐数据扩展首片功能。硬护栏须有对应验收用例，不能以没有样本或价值指标尚未成熟为由免验；验收通过也不等于已经证明长期学习价值。
- 优先复用本地事实和审计记录，不为指标额外复制原始文本、凭据或私密摘录；测量、汇总和导出均受既有权限和彻底删除规则约束。具体字段、窗口时长和报表工具属于工程规格，不在本次决定。

### 11.6 需求性质、交付范围与首片编号

PRD 中的终局方向和首片要求使用两个独立维度标记，避免把愿景误当成本轮交付：

**需求性质**说明一条内容是什么：

- `不变量`：跨阶段必须遵守的事实、权限、证据、状态或数据安全规则；
- `功能`：用户或系统需要提供的具体能力。

**交付范围**说明当前做到哪里：

- `事实门`：首片验收门一；
- `证据门`：首片验收门二；
- `后续`：不进入首片，未来单独规划；
- `暂缓`：当前明确不进入实现规划。

一条不变量可以同时属于首片范围。例如原始产出不可篡改、权限不能越权、AI 失败时仍保存产出，既是跨阶段规则，也必须在事实门或证据门验收。反过来，终局正文出现的功能不自动成为首片任务。

“待工程规格分解”是准备状态，不是交付范围。首片要求同样必须先完成领域、事件、API、迁移、测试和恢复规格，后续功能也不能因为已经写入终局正文就跳过工程规格。

## 12. 开发流程与阶段门

### 12.1 进入编码前

- 以本 PRD 和决策记录冻结产品边界；
- 编写领域模型与状态转换规格；
- 编写 Core 命令、事件、投影和 API 契约；
- 编写首个纵切片的实施计划、测试计划和数据迁移/恢复计划；
- 明确新迁移从 `011_*.sql` 开始，旧迁移 `001`-`010` 不原地修改；
- 在隔离数据库演练，不触碰默认用户数据库。

### 12.2 实施顺序

1. 验收门一：领域对象、事件、投影、学习委托、会话和文本产出事实链；
2. 验收门一回放、隔离和权限测试通过；
3. 验收门二：证据主张、状态派生、复核卡、质疑和撤销；
4. 新领域计划/学习行动入口与新证据闭环连接；旧固定模型和旧入口不在首片范围内；
5. 后端单元/集成测试、前端交互测试和 Playwright 验收；
6. 隔离数据库迁移、恢复和回放验证；
7. 用户验收通过后，另行评估默认数据库迁移，未经明确授权不应用。

### 12.3 完成标准

一个纵切片只有在领域规则、数据安全、用户流程、自动化测试和恢复路径同时成立时，才可描述为“完成”。只完成接口或模型，不能宣称长期学习协作者已经实现。

## 13. 明确暂缓

以下能力不进入首个纵切片，也不改变本 PRD 的核心承诺：

- 云端同步、P2P、CRDT、桌面封装和 Android 客户端；
- Embedding、向量数据库和完整知识库；
- 完整甘特图资源约束和最优排程；
- 复杂附件、Web Search、开放网络 Agent；
