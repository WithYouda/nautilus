## 1. 背景与目标

当前数据层已经存在完整四层关系：

```text
学习目标（界面称“计划”）
  -> 科目
    -> 主题
      -> 任务
```

问题不在于缺少层级，而在于当前页面把“多个计划选择、计划结构浏览和节点编辑”同时压进固定的左右分栏，导致用户难以先看清全部计划，也难以在任务很多时高效编辑。首页右栏 AI 又始终绑定当前任务，无法承担跨计划分析。

本设计完成以下目标：

- 计划入口先展示全部计划，再明确进入一个计划详情。
- 单计划详情使用 `概览 / 结构 / 排期` 三个子视图，各自只承担一种主要工作。
- “结构”采用文档式层级大纲，层级展开与节点编辑彻底分离。
- 科目进度与近期任务在概览中上下排列，不再争夺横向宽度。
- 任务完成与撤销完成都成为可靠、可持久化、可测试的领域行为。
- 首页、计划详情和任务入口分别提供全局、计划级和任务级 AI，但复用同一套对话、模型、运行和历史管理代码。
- 保持现有 Nautilus 岩砂航海日志视觉、固定工作区、计时器边界和 AI 学习室布局，不重新设计整套产品。

## 2. 本轮范围与非目标

### 2.1 本轮范围

- 全部计划总览清单。
- 单计划详情外壳和稳定返回路径。
- 计划概览、文档式结构编辑和最小可用排期视图。
- 科目、主题、任务的新增、编辑、排序和软删除入口重排。
- 任务完成/撤销完成的后端语义和前端入口。
- 全局、计划、任务三种 AI 上下文范围的持久化与恢复。
- 桌面、浏览器放大等效窄视口和移动端适配。

### 2.2 非目标

- 不在本轮实现 AI 自动写入计划、自动重排或自动生成完整计划。
- 不实现任务依赖、完整甘特拖拽、容量优化或资源平衡。
- 不实现附件、Web Search、思考强度和自定义请求参数。
- 不重做 AI 提供方、对话历史、标题生成或消息渲染。
- 不把计划树扩展状态同步到后端或跨设备同步。
- 不引入新的前端路由框架、状态管理框架或第二套 AI 运行服务。

## 3. 术语与产品语义

- 数据库 `learning_goal` 在界面统一称“计划”。“目标”仍是计划的意图和结果，不再作为额外一层 UI 节点重复显示。
- 一个计划可以包含多个科目；一个科目包含多个主题；一个主题包含多个任务。
- “下一项”不是下一个计划，而是该计划中下一条可执行的未完成任务。
- 全局 AI 面向整个学习工作区；计划 AI 面向一个 `learning_goal`；任务 AI 面向一个具体 `task` 及其祖先路径。
- 选择或编辑某个任务节点不会自动把右侧 AI 从计划级切成任务级。只有点击明确的“任务 AI”入口才会切换。

## 4. 页面信息架构

### 4.1 计划总览

进入工作区“计划”视角后，第一屏始终是全部计划清单，不再自动选中第一条计划并直接打开编辑器。

页面顺序：

```text
页面标题与“新建计划”
总体指标
计划清单
```

每条计划使用紧凑的全宽列表行，不使用卡片套卡片。列表行至少展示：

- 计划标题、状态和日期范围。
- 科目、主题、任务数量。
- 完成任务数与总体进度。
- “下一项”任务标题和所属科目/主题。
- “打开计划”入口。

点击计划行主体或“打开计划”进入该计划详情的“概览”。点击“下一项”直接进入该计划“结构”，仅展开该任务的祖先路径并定位任务行。

### 4.2 “下一项”稳定规则

后端按以下优先级计算每个计划的下一项，前端不得自行从数组猜测：

1. 该计划中存在运行中或暂停中的真实 `study_session` 时，返回对应任务。
2. 否则从未删除、未取消、未完成的任务中排序。
3. `in_progress` 排在 `pending` 前。
4. 已逾期任务按最早截止日期优先。
5. 其余任务按 `planned_start`、`due_date`、层级 `position`、`created_at` 和 `id` 稳定排序。
6. 没有候选任务时显示“暂无待办”；若所有有效任务均完成，可附加“计划任务已完成”。

草稿、已完成和已归档计划仍可显示，但状态必须明确；已归档计划默认不进入活动清单，后续可由筛选入口查看，本轮不扩展归档管理。

### 4.3 单计划详情

详情页顶部顺序固定为：

```text
返回全部计划 / 面包屑
计划标题、说明、状态、日期和汇总数据
计划设置 / ＋科目
概览 / 结构 / 排期
当前子视图内容
```

`＋科目` 必须位于计划标题区域右侧，与计划本身建立清楚的父子归属；不得放在“计划结构”文字右侧。

从计划清单进入时默认打开“概览”。同一浏览器会话内返回该计划时，必须恢复最近子视图；从任务、下一项或任务深链进入时，目标节点优先并强制打开“结构”。不存在或已删除的计划/节点必须回退到计划总览并显示可行动提示。

实现使用现有工作区状态与 History API，并把计划 ID、子视图和可选目标节点编码到 URL 查询参数；不引入 React Router。刷新后必须从 URL 恢复这些状态，不得只依赖不可恢复的 React 临时状态。

## 5. 概览子视图

概览用于判断计划健康度，不承担树形编辑。内容顺序为：

1. 紧凑指标带：总体完成、已完成任务、本周待完成、计划学习量。
2. 科目进度：全宽纵向列表。
3. 近期任务：位于科目进度下方的全宽列表。

科目进度和近期任务必须是上下平行关系，不得在中栏中左右各占一半。这样在 `1024x640` 等效视口下仍能保留可读列宽。

进度计算规则：

- 分母为未删除且未取消的任务数。
- 分子为其中 `completed` 的任务数。
- 没有有效任务时显示 `0%`，不显示误导性的 `100%`。
- 学习时长使用任务预计时长汇总；实际时长单独标注，不混入完成比例。

近期任务使用与“下一项”一致的稳定排序。任务行可打开任务、切换完成状态或进入任务 AI；这些操作均不得隐式改变右栏计划 AI 的上下文。

## 6. 结构子视图

### 6.1 主内容表面

结构是中栏的主要内容，不再永久占用一个窄树侧栏。大纲按以下层级呈现：

```text
科目
  主题
    任务
    当前节点的内联编辑器
```

计划本身已经在页面标题中表达，不再重复渲染为树根节点。所有科目行始终可见；主题和任务按展开状态显示。

### 6.2 解决“默认折叠很奇怪”

根本处理方式不是默认展开整棵树，而是把“概览”和“结构”分开，并让结构页只自动揭示一个有意义的焦点路径：

- 从任务或“下一项”进入时，只展开该任务的科目和主题祖先。
- 用户本次会话已经操作过该计划时，恢复仍然有效的展开节点。
- 首次直接进入结构、且没有目标节点时，自动展开“下一项”所在的科目和主题，但不自动打开编辑器。
- 没有下一项时只展示全部科目行，不伪造默认选择。
- 其余分支保持折叠，后续展开完全由用户操作。

展开状态按计划 ID 存入 `sessionStorage`，刷新和同一标签页返回时保留；浏览器会话结束后可清除。已删除或移动后不存在的节点 ID 在恢复时直接忽略。展开状态不是业务数据，不新增数据库字段。

结构工具区提供“收起全部”和“展开到主题”两个用户主动触发的批量命令；不得在数据加载完成后自动执行。

### 6.3 单一职责交互

每个控件只承担一种行为：

- 展开箭头：只展开或收起子层级，设置正确的 `aria-expanded`。
- 节点名称：只打开该节点的内联编辑器。
- `＋科目`：在当前计划下创建科目。
- `＋主题`：只出现在科目行，创建该科目的主题。
- `＋任务`：只出现在主题行，创建该主题的任务。
- 任务复选框：只切换完成/未完成，不选择节点、不打开编辑器。
- “任务 AI”：明确进入任务级 AI。
- 更多菜单：承载上移、下移和软删除等低频操作。

图标使用现有 Lucide 图标并提供 tooltip/`aria-label`。页面不常驻显示“箭头用于展开”等操作说明文字。

### 6.4 单内联编辑器

同一时间最多打开一个编辑器。编辑器紧邻对应节点下方，并保持与节点相同的缩进语义：

- 整行称“任务节点行”，其中标题和摘要所在的主要点击区称“任务节点主区域”；前端组件建议命名 `TaskOutlineItem`。
- 点击任务节点主区域时，在该任务行下方打开编辑器。
- 再次点击当前任务节点主区域时，收起当前编辑器并清除选中状态。
- 点击另一任务节点主区域时，先收起当前编辑器，再把同一个编辑器移动到新任务行下方并载入新任务数据。
- 任务复选框、任务 AI 和更多菜单是独立操作区，点击时不得打开、关闭或切换编辑器。
- 科目和主题编辑器提供名称、保存、取消和软删除。
- 任务编辑器复用现有任务字段：名称、类型、排期方式、开始/截止日期、可选具体时间、预计时长、计时方式及进度/状态展示。
- 计划本身通过标题区“计划设置”编辑，不在大纲中再开一个根节点编辑器。
- 新建成功后父层级保持展开，并打开新节点编辑器；创建失败时保留输入。

### 6.5 未保存修改保护

编辑器必须基于初始值计算 dirty 状态，不能仅在任意输入事件后永久标脏。

用户在 dirty 状态下执行以下动作时，统一显示三选一确认：

- 切换节点。
- 新建其他节点。
- 切换概览/结构/排期。
- 返回全部计划或切换计划。
- 进入全局、计划或任务 AI。

选项语义：

- 保存：校验并保存；成功后继续原动作，失败则留在编辑器。
- 放弃：恢复服务端值并继续原动作。
- 继续编辑：关闭提示并停留原处。

浏览器刷新或关闭使用原生 `beforeunload` 提示。本轮不引入自动保存。

## 7. 排期子视图

本轮提供计划范围内的最小可用排期，不伪装完整甘特图：

- 只显示当前计划的任务。
- 按日期分组，展示开始/截止日期、具体时间、状态、预计时长和所属路径。
- 支持复用现有单任务按天前移/延期操作。
- 支持打开任务、切换完成状态和进入任务 AI。
- 提供“在学习日历中查看”入口，进入全局日历时保留当前计划筛选。

任务依赖线、批量拖拽和自动负载平衡继续留在后续甘特阶段。

## 8. 可逆任务完成

### 8.1 领域语义

完成和撤销完成必须是服务端领域操作，不得只修改前端数组：

- 标记完成前保存任务原 `status` 和 `progress`。
- 标记完成后设置 `status=completed`、`progress=100` 和 `completed_at`。
- 再次点击复选框时恢复完成前的 `status` 和 `progress`，并清空 `completed_at`。
- `actual_minutes`、已经结束的 `study_session` 和历史记录全部保留。
- 如果完成时存在活动计时，沿用现有行为结束并结算该会话；撤销完成不会自动重启旧计时。
- 恢复到 `in_progress` 只代表任务状态恢复，不代表存在活动计时；活动计时判断必须以 `study_session` 为准。
- 已取消任务不提供完成复选框，必须先在编辑器中恢复为可执行状态。

### 8.2 迁移 `009_task_completion_restore.sql`

为 `task` 新增：

```text
completion_restore_status   nullable text
completion_restore_progress nullable integer
```

约束范围与现有任务状态、进度一致。首次从非完成状态切到完成时写入；对已经完成的任务重复请求不得覆盖。成功撤销后清空两个恢复字段。

迁移前已经完成的旧任务无法恢复未知历史值。对此使用明确兼容规则：第一次撤销时恢复为 `pending / 0%`，同时保留学习时长和会话历史；之后的完成/撤销均可精确恢复。

### 8.3 API

新增幂等接口：

```text
PUT /api/tasks/{task_id}/completion
{ "completed": true | false }
```

现有 `POST /api/tasks/{task_id}/complete` 暂时保留并委托给同一领域方法，避免破坏今日页和旧前端调用。所有返回值使用更新后的完整任务对象。

## 9. 全局、计划和任务 AI

### 9.1 共用运行链路

三种 AI 不是三个独立 Agent 或三个常驻服务。它们共用：

- provider/model 选择和配置快照。
- Conversation、Message、Chat Run、Title Run 和 SSE。
- 对话历史、改名、软删除、取消、刷新恢复和错误处理。
- 同一套 AI 学习室组件。

唯一差异是对话持久化的 `context_scope`、主关联目标和每次 Run 冻结的上下文快照。

### 9.2 上下文范围

| 范围 | 默认入口 | 持久化关联 | 上下文内容 |
| --- | --- | --- | --- |
| `global` | 首页/计划总览右栏 | 无主节点关联，但范围必须持久化 | 活动计划汇总、各计划进度、今日/逾期/近期任务和冲突摘要 |
| `plan` | 单计划详情右栏 | `conversation_link(primary, goal)` | 当前计划信息、科目/主题汇总、任务状态、排期、进度和学习量 |
| `task` | 明确点击任务 AI | `conversation_link(primary, task)` | 任务字段、完整祖先路径、相关排期、进度和学习记录摘要 |
| `independent` | AI 学习室独立入口 | 无主关联 | 不自动注入计划数据 |

上下文必须结构化、可预览并受预算限制，不把所有数据无边界拼进提示词：

- 全局优先保留活动计划、逾期项、今日项和最近截止项。
- 计划级保留完整科目/主题汇总，并按优先级截断任务明细。
- 任务级保留当前任务和祖先路径，不自动扩展到其他计划。
- 截断时在快照元数据中记录总数、已包含数量和截断标记。
- 每个 Chat Run 继续冻结实际上下文快照，后续计划变动不得改写历史 Run 看过的内容。

### 9.3 迁移 `010_ai_conversation_scope.sql`

为 `conversation` 新增：

```text
context_scope TEXT NOT NULL DEFAULT 'independent'
CHECK context_scope IN ('independent', 'global', 'plan', 'task')
```

为 `context_snapshot` 新增精确的 `scope_kind`，取值同上。现有 `source_kind` 保留作为兼容字段，不原地重写 `005`。

回填规则：

- 有 task 主关联的既有对话回填为 `task`。
- 有 goal 主关联的既有对话回填为 `plan`。
- 没有主关联的既有对话保持 `independent`，不得自动改成 `global`。

### 9.4 创建与恢复

对话创建接口扩展为显式范围：

```text
POST /api/ai/conversations
{
  "context_scope": "independent | global | plan | task",
  "target_id": "plan/task 范围必填",
  "title": "可选"
}
```

旧 `task_id` 请求在过渡期兼容映射为 `task`，但新前端统一使用显式范围。

恢复规则：

- 首页右栏恢复最近的 `global` 对话；没有时进入全局空白新对话。
- 计划详情恢复该 goal 最近的 `plan` 对话。
- 任务 AI 恢复该 task 最近的 `task` 对话。
- 新建对话继承当前入口范围和目标。
- 独立对话不会覆盖全局、计划或任务对话的最近记录。

### 9.5 右栏行为

- 计划总览右栏显示“全局 AI”，摘要全部活动计划。
- 单计划详情右栏显示“计划 AI”，始终保持当前计划上下文。
- 点击大纲节点、切换编辑器或勾选任务，不自动改变右栏范围。
- 任务行和近期任务中的“任务 AI”是唯一的任务级切换入口。
- 范围标签用于说明当前上下文，不伪装成会自动猜测目标的模式开关。
- AI 产生的计划修改仍只生成草案；正式写入继续需要用户确认，本轮不实现该写入链路。

## 10. 数据接口与加载策略

当前 `GET /api/plans` 会返回所有计划的完整树，不适合计划数量和任务数量增长后的总览页。本轮拆分读取职责：

```text
GET /api/plans/summary
  返回计划行所需汇总、进度和下一项，不返回完整任务树

GET /api/plans/{goal_id}
  返回单个计划的完整四层树和汇总

GET /api/plans/{goal_id}/schedule
  返回当前计划的排期任务列表
```

现有 `GET /api/plans` 在过渡期保留，避免一次性破坏今日页和其他调用；新计划总览与详情不再依赖它加载全部树。

汇总、下一项和计划详情查询均必须排除软删除节点，并使用稳定排序。列表加载、详情加载和节点 mutation 分别显示自己的 loading/error 状态，不能因右栏 AI 失败而阻断计划编辑。

## 11. 响应式与视觉约束

- 延续现有岩砂、炭灰、铁锈红、细规则线和低圆角系统。
- 不增加渐变装饰、浮动大卡片、卡片嵌套或与现有产品脱节的视觉语言。
- `1440x1000`：保留左导航、中栏和右侧 AI；结构大纲占据中栏主宽度。
- `1024x640`：右侧 AI 收入由计划标题区图标打开的抽屉；中栏不再为隐藏侧栏预留宽度。
- `390x844`：单列页面；计划头操作可换行；次要节点操作进入更多菜单；内联任务编辑器改为单列字段；AI 使用抽屉。
- 任意档位不得出现页面级横向溢出、按钮遮挡节点名称或内联编辑器超出大纲边界。
- 完成勾选、展开箭头、节点名称和更多菜单必须保留稳定点击区域，状态变化不得引起整行跳动。
- 活动计时器继续使用既有 Portal 和视口钳制，不得因计划页改造重新进入内容流。

## 12. 错误与并发边界

- 节点保存失败：保留编辑器、dirty 状态和用户输入，错误显示在编辑器内。
- 节点被软删除：详情刷新后关闭失效编辑器，回到最近有效父节点，并显示提示。
- 删除存在活动计时的分支：沿用后端拒绝规则，不做前端假删除。
- 完成切换失败：复选框回滚服务端状态并显示错误，不保留虚假完成状态。
- AI 上下文构建失败：计划页面仍可编辑；学习室显示具体错误，不创建空白成功快照。
- 同一任务的完成请求必须幂等；重复 `completed=true` 不覆盖恢复值，重复 `completed=false` 不继续改变状态。
- 当前有未保存编辑时，任何异步刷新不得用服务端响应直接覆盖本地表单。
