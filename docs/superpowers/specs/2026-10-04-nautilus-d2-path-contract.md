图形状态来自路线采纳及checkpoint：主线实线、暂停历史分支虚线、候选点线，当前位置有文字标记。任务完成显示任务事实，证据支持显示独立依据入口；不以一个节点颜色合并“做完”和“已掌握”。旧数据没有路线时提供“建立路径”，从本次明确采纳开始历史。

## 3. Core命令、事务与API建议

所有正式写入沿用`Core.execute(principal, command, idempotency_key)`及现有事件追加/投影。新增命令extra=forbid、owner/plan/ref校验、独立stream CAS、相同key同请求返回原结果、同key异请求拒绝。查询no-store；冲突409保留本地草案，重新读取并重做影响预览，不能静默重试覆盖。

| 命令组 | 拟定命令/事件 | 约束及前端入口 |
| --- | --- | --- |
| 组织 | Create/Rename/MoveModule；ReorderPlanChildren；MovePlanTask；`organization.*` v1 | 同计划；父模块不可自己/后代；同父级模块与任务混排；传完整同级ID列表防漏项。默认任务直挂计划 |
| 计划/单任务确认 | CreateLearningPlan(goal_id可空)、ConfirmPlanTask；`plan.created/plan_task.confirmed`及对应组织插入事件 | 明确支持无目标计划的创建及追加；复用任务/成果/委托建立校验，不改旧setup事件。未来旧“添加下一步”也须同事务通知新组织stream，防排序/CAS漏记 |
| 路线草案/采纳 | SavePathDraft；ConfirmPathDecision；`path.draft_saved/path.decision_confirmed` | 草案可编辑但不正式；确认携带preview_id和期望path/org/commitment revisions及受影响action/session versions |
| 同线位置 | SetPathPosition或带明确node_id的StartCommitmentItem；`path.position_selected` | 点节点只是选中。点关联任务“开始/继续”才明确定位到该节点，同事务记录原位置；普通任务切换不产生长期分叉 |
| 安排 | SaveCommitmentDraft；ConfirmCommitment；Skip/DeferItem；Start/ContinueItem；`commitment.*` | 逐项保留/替换/延期；有实际执行的项不抹除。开始复用StartSession；从运行中继续不重复创建 |
| 反馈/来源 | Record/CorrectSessionFeedback；ClassifySignalOrigin；`session.feedback_recorded/corrected/signal.origin_classified` | 可跳过，纠正追加revision；真实性、时长来源和结果来源分开，不把自报变成平台核验 |

无目标的ConfirmPlanTask不插入要求goal_id非空的旧learning_setup，也不生成虚假goal。新计划创建及任务确认事件各自表达真实对象，保持旧setup可回放。

拟定路由统一在`/api/learning/plans/{plan_id}`下：`organization`及`modules`/`children-order`/`tasks/{id}/placement`；`path`、`path/drafts`、`path/previews`、`path/decisions`；`commitments`、`commitments/drafts`、`commitments/previews`、`commitments/confirm`及`items/{id}/start|continue|defer|skip`。反馈用`/api/learning/sessions/{session_id}/feedback`；AI建议运行读写独立端点，不能以生成接口写正式计划。实际schema及路由定义随各切片一并核对，不一次搭空框架。

**路线确认事务：** 重读目标/计划与全部依赖 → 核对预览指纹及版本 → 按预览正常中断受影响的本计划运行会话，追加原action的session.ended事件 → 保存旧checkpoint → 写新路线决定及主线/位置 → 写同一预览中明确接受的未执行安排变化 → 提交。任何一步失败全部回滚。未受影响任务、其他计划、原始产出/证据不改；不启动新会话、不发送AI。生成中的详细交互见第6节待审阅项；不在数据库事务中等待网络，迟到结果不能改变正式路线/安排。

同一主线内开始关联任务只改变明确位置；从计划任务列表学习一个路线外任务时保留主线，显示“当前正在学习：…（未关联这条路线）”及可选定位入口。完成任务不自动采用下一节点，也不宣告阶段/目标达成。

恢复/撤销以**新决定**重新采用所选历史版本和可用位置，不逆向删除事实。已完成任务只提供回看；想再次练习须明确创建新的安排/委托，不重开已完成事实。旧checkpoint跨库引用不存在/隐藏/清除时，仅显示可读的路线/任务与缺失原因，由本人选新位置，不使用全库最近记录替代。

## 5. 校准规则表（作者已接受）

### 5.1 来源与四个时间字段

用户可投入预算B、任务预计范围E=[lo,hi]、本人记录的有效投入A（精确值或范围）、session自然跨度S分别保存。A不能由S或B补出；E为本人估计或AI建议并标来源，缺失不补造。执行反馈可选“投入约…分钟/不确定”“任务大小：合适/太大/太碎”“节奏：合适/太紧/想多安排一些”，不增加强制结束问卷；历史可纠正。用户记录不称自动计量。

| 信号 | 准入和去重 | 缺失/矛盾/过期处理 |
| --- | --- | --- |
| 真实执行 | 明确source origin为real；实际session＋可追溯产出/作答/本人执行反馈至少其一。相同安排项为同一工作块，多次中断继续不累计独立样本；另一次独立练习须有新安排/明确新工作块关联 | 打开、AI讲完、未来安排、单纯session结束不算有效学习；不足留未知，不以最低分钟数判无效 |
| 代表性覆盖 | 同方向可比较情境至少两类，例如理解＋应用，或同技能的两个实际输入情境；按任务/成果/活动来源判，不按标题猜 | 单类重复可帮助估时间，不能据数量宣称覆盖广；无关计划不合并 |
| 投入匹配 | 同工作块的E与纠正后A，粒度一致且真实；有效比较至少两对才能建议3–7次。A为范围时只有整个范围落在E内才记符合，部分交叠为未知 | 大段挂机跨度不使用；前后标准/任务范围不同不硬比。不算一个“效率得分” |
| 学习表现 | 至少一个实际回忆/变式/迁移尝试，有保存作答/作品及可追溯反馈；教学反馈、本人外部报告、合格标准验证分列，并保留帮助条件 | 没有正式标准也可给短安排或以“任务表现反馈”支持有限扩展；不生成能力状态。相矛盾且影响下一步时建议短安排补信号；AI夸奖/出题没有实际作答不准入 |
| 个人负担/粒度/教法 | 本人对已经执行的任务及采用教法有明确反馈；实际体验与仅选择了某教法分开，想多安排只是偏好 | 表示“太紧/太大/方式不合适”可立即建议拆分/缩短/换法；中断/跳过不推断能力失败，未说明原因不猜负担 |
| 节奏/可用时间 | 本人给出接下来可用时段/每周预算与连续区块上限；实际执行与原安排对比，允许明确改期后再比较 | 日期过去不算失败；没有未来可用时间不提供具体一两周日期表。只给任务顺序/时间范围 |
| 真实性/旧历史 | 用途origin=real/demo/test/unknown，分类依据basis=normal_user/user_report/demo_script分别保存；normal_user本身不认证real。本人在可选反馈明确“实际学习”后标real+user_report，旧历史同样可核对；已知demo/test及派生结果排除。已有D1演示以稳定context、命令namespace及明确来源识别，不靠名称 | 未标用途保留unknown，不自动升档；用户可记录试功能。trial开发环境不让全部记录自动真实或全部作废；已知合成来源不可改成真实。清除/来源撤权退出输入 |

真实性只说明记录用途，不证明结果独立/有效。新的校准输入分类是审计元数据，不能修改旧事实；后续演示脚本必须写明确标记。开始D2时不自动认证旧历史，也不要求作者填完历史才可继续。

### 5.2 分轴覆盖与情境规则

遵守产品决定13.3：不用一套固定数量作为所有任务的硬门槛。Core先看本次建议是否仍在已观察情境内，再分别判断执行、学习表现、投入、粒度/教法及节奏的覆盖和未知；数字是通常情境下需要核对的参考量，不能单独升档或因缺一个数机械拒绝。AI只能解释已核查的规则结果。

具体分支建议：①新方向/新情境或影响下一步的矛盾未解决，保持1–3次探测；②同范围小幅延展，真实作答及匹配反馈已支持下一项、本人负担和教法反馈明确且无冲突，可给3–5次任务顺序；投入未知时不提供精确耗时或日期；③要扩到不同情境/更大范围，先核对拟安排的每类任务均有代表性执行/表现及匹配的投入/体验来源，覆盖成立才建议最多7次，未知部分先拆成短探测。不能以统一样本数量代替这三种风险判断。

只使用计划内当前方向/范围适用的最近最多7个独立有效工作块，以及每类任务最近可用的代表性来源；更早来源单列且说明范围。Core校准和AI输入采用相同准入：计划/任务身份不授权读取其他对话的C2观察，当前路径外观察不自动进入计划摘要或校准，跨路径使用另行确认。方向/预计粒度/可用时间改变只重新校准相应轴，原成果证据保持。

| 输出 | 建议规则 | 呈现/确认 |
| --- | --- | --- |
| 1–3次 | 初次、关键覆盖不足、方向实质改变、来源矛盾未核对、本人负担过重。默认提出2次；只有一个清楚的下一步则1次，可编辑到3次 | “先安排接下来两次”；主要未知放依据详情。仍可直接开始/手动安排 |

补充：没有足够学习表现时允许手动安排更远内容，但系统不因此宣布已校准；只估时的信号不冒充学习效果。非同方向、不同范围样本可显示为历史参考，不参与本方向窗口。用户改变可用时间后节奏稳定标记失效，投入/表现等仍按适用范围保留，不能仅因空闲了更多天复活稳定结论。

首版不设“过了多少天自动降档”或统一证据有效期。每次点更新重新校验活跃引用、规则版本、当前方向/任务粒度、最新可用时间；旧时间安排超过其明确覆盖日期后只能给无日期短建议或询问新时间，不能沿用过去一周的空闲表。能力证据过期按原达成标准处理，与安排校准分别解释。
