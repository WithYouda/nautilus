| 项目 | 内容 |
| --- | --- |
| 产品名 | 学海无涯 |
| 英文名 / 内部代号 | Nautilus |
| 文档版本 | 1.0 |
| 创建日期 | 2026-07-23 |
| 状态 | 设计已确认，待书面审阅 |

## 1. 产品定位

学海无涯是一款面向深度自学者的本地优先 AI 学习管理助手。首要服务考研学习，其次支持计算机等专业知识学习，再兼顾需要整理 AI 对话的知识工作者。

核心闭环：

```text
创建目标或计划
  -> 查看今日任务
  -> 开始计时学习
  -> 完成任务
  -> 可选生成学习记录、知识卡片或大纲
  -> 在相关对话中继续学习
```

核心差异化是对话分支和知识追溯：用户可以从历史消息创建新的学习探索路径，而不是破坏原始对话；每个知识产出都能追溯到消息、资料和计划节点。

## 2. 设计原则

1. **本地优先**：AI 调用、业务逻辑、计划计算、资料解析、全文检索和 SQLite 均在用户设备本地运行。
2. **人在回路**：AI 可以提出计划和变更，但持久化修改必须经过用户确认。
3. **原始内容可追溯**：消息、分支来源、知识卡片来源和 AI 执行记录保留关联。
4. **渐进复杂度**：保留四层计划和完整甘特图，但用分阶段实现降低一次性开发风险。
5. **派生数据可重建**：搜索索引、缓存和临时结果不作为唯一数据源。
6. **低依赖运行**：首版不依赖微服务、Redis、Celery、Milvus 或多个常驻 Agent 进程。

## 3. 首阶段产品边界

### 3.1 运行方式

首阶段只实现 Web MVP：

- React/TypeScript 网页和 Python 本地服务运行在 WSL2。
- Windows 宿主机通过 WSL2 实际 IP 访问，不使用 `localhost` 作为交付地址。
- 服务绑定 `0.0.0.0`，启动时输出当前实际访问地址。
- SQLite、资料库、AI 工作流和本地索引均存放在 WSL2。
- 本阶段不实现 Windows 桌面封装、Android 客户端或跨设备同步。

### 3.2 计划系统

保留四层结构：

```text
学习目标
  -> 科目 / 领域
    -> 章节 / 主题
      -> 可执行任务
```

任务类型包括学习、练习、复习和知识产出。计划创建方式全部支持：

- 完全手动创建。
- 用户填写少量信息后由 AI 快速生成。
- AI 对话与结构化表单结合的引导式创建。

三种方式最终都进入同一个可编辑计划编辑器。

任务支持：

- 日期范围和预计学习时长。
- 可选的具体开始、结束时间。
- 固定日程或灵活进度。
- 25/5、50/10、自定义番茄钟，以及普通计时。
- 开始、暂停、继续和结束。
- 自动记录开始时间、结束时间和累计学习时长。
- 默认一键完成。
- 任务延期时，默认由 AI 提出重排建议并等待确认；自动顺延和保持逾期作为可选设置。

### 3.3 计划视图

首阶段包括：

- 今日学习驾驶舱。
- 任务列表。
- 日历视图。
- 完整可编辑甘特图。
- 首页模块可自定义显示、隐藏和排序，默认使用今日学习驾驶舱布局。
- 设置中提供系统布局模板；应用模板后仍可继续修改。
- 修改后的布局可以另存为个人模板，支持重命名、再次应用和删除，系统模板不可覆盖。

甘特图支持：

- 四层计划展开和折叠。
- 拖拽调整开始时间、截止时间和持续时间。
- 批量移动相关任务。
- 显示进度、逾期状态和依赖关系。
- 四类依赖：完成后开始（FS）、同时开始（SS）、同时完成（FF）、开始后完成（SF）。
- 依赖提前量或延迟量。
- 循环依赖检测。

资源约束、自动负载平衡和基于容量的最优排程属于远期规划，不进入首阶段。

### 3.4 AI 对话与分支

首阶段包括：

- 普通线性对话。
- 计划内对话和独立对话。
- 一个主要计划关联和多个辅助计划关联。
- 从任意历史消息创建分支。
- 创建后自动切换到新分支。
- 原分支保持不变。
- 窄轨分支图常驻显示。
- 点击放大入口进入全屏画布。
- 全屏画布首阶段支持查看、缩放、平移、选择和切换分支。
- 移动 Web 中，分支侧栏变为底部抽屉或悬浮入口，展开后显示横向流程图。

放大入口必须保留。分支合并、拖拽重构关系和复杂连线编辑属于后续能力，首阶段不隐藏入口，但可以明确标注为开发中或暂未启用。

首阶段不做分支合并和文本级 Diff。后续合并采用知识块级方式：AI 生成观点对比卡片，用户勾选和编辑后生成新的合并结论节点，不修改原始分支。

### 3.5 AI 产出

首阶段支持：

- Markdown 层级大纲。
- AI 学习记录草稿。
- 分支摘要。
- 可编辑知识卡片。
- `.md` 预览、编辑和导出。

`.xmind` 文件生成和外部思维导图工具调用属于后续阶段。

AI 学习记录默认为草稿，用户确认后才写入正式学习记录。

### 3.6 资料库与检索

首阶段支持导入：

- PDF。
- Markdown。
- TXT。

PDF 只处理包含文本层的文件，不做扫描版 PDF OCR。导入文件复制到 Nautilus 本地资料库，由应用统一管理；首阶段不支持仅引用原始路径。

检索使用 SQLite FTS5：

- 检索历史消息、资料文本和知识卡片。
- 不引入向量数据库或 Embedding 模型。
- FTS5 索引属于可重建派生数据。
- 检索层保留接口，后续可增加混合检索或本地 Embedding。

### 3.7 提醒与备份

首阶段提供应用内提醒和浏览器通知：

- 任务即将开始。
- 任务即将截止。
- 任务逾期。
- 番茄钟阶段切换。
- AI 或本地后台任务完成。

浏览器关闭后的 Windows 原生后台通知不属于首阶段。

备份采用自动快照加手动备份包：

- 每 24 小时在空闲时创建 SQLite 一致性快照。
- 默认保留最近 7 份每日快照和 4 份每周快照。
- 数据库迁移前额外创建快照。
- 手动备份包含数据库、资料文件、附件和哈希清单。
- API 密钥、缓存、FTS5 索引和临时文件不进入备份。
- 恢复前自动备份当前数据，并校验版本和文件哈希。
- 首阶段备份包默认不加密，导出时明确提示其中含私人学习内容。

## 4. 总体架构

```text
Windows 浏览器
    | WSL2 实际 IP + 本地访问令牌
    v
React / TypeScript Web UI
    | HTTP + SSE + WebSocket
    v
FastAPI 本地核心服务
    |-- 计划与任务模块
    |-- 计时与提醒模块
    |-- 对话与分支模块
    |-- 知识产出模块
    |-- 资料解析与检索模块
    |-- LangGraph 工作流模块
    |-- 备份与后台任务模块
    |
    |-- SQLite WAL + FTS5
    |-- Nautilus 本地资料库
    |-- 本地加密凭据文件
```

技术选择：

- 前端：React、TypeScript、Vite。
- 分支图：React Flow 或同类 React 节点画布组件。
- 后端：FastAPI、Python。
- AI 工作流：LangGraph；首阶段不同时引入 CrewAI。
- 数据库：SQLite，启用 WAL、外键和迁移机制。
- 搜索：SQLite FTS5。
- 实时输出：SSE 用于 AI 流式文本，WebSocket 用于计时、任务和后台作业状态。
- 甘特图：使用独立的甘特图组件，不能让甘特图直接绕过领域服务修改数据库。

长任务通过 SQLite 持久化任务表和单进程后台执行器运行。首阶段不使用 Redis、Celery、Milvus 或多个常驻 Agent 进程。

## 5. 本地访问与凭据

### 5.1 无账号身份模型

首阶段不提供注册、登录或云端账号。

- 首次启动自动创建本地用户和设备标识。
- 服务启动时生成随机访问令牌。
- 浏览器首次访问完成本地授权后建立短期会话。
- 会话使用 `HttpOnly` 和 `SameSite=Strict` Cookie。
- 令牌不写入 URL 查询参数、访问日志或浏览器历史。
- 设置中支持撤销会话和轮换访问令牌。

这属于本地服务访问控制，不改变产品的“无登录”体验。

### 5.2 AI API 密钥

- API 密钥只保存在本地加密凭据文件中。
- 凭据文件与 SQLite 分离，仅当前 WSL2 用户可读。
- 密钥不进入数据库、日志、备份包、对话内容或未来同步数据。
- 设置页面只显示掩码，并提供连接测试。
- 通过 `CredentialStore` 接口封装，未来桌面端可接入 Windows Credential Manager。

## 6. 数据模型

### 6.1 计划域

实体包括：

- `learning_goal`
- `subject`
- `topic`
- `task`
- `task_dependency`
- `schedule_entry`
- `study_session`

任务依赖单独建模，支持 FS、SS、FF、SF 和提前/延迟量。所有写入通过领域服务和事务完成。

### 6.2 对话域

实体包括：

- `conversation`
- `message`
- `branch`
- `conversation_link`
- `context_snapshot`
- `ai_run`

消息采用追加式记录。分支保存父分支、来源消息和上下文快照引用。主要关联决定默认上下文和归档位置，辅助关联用于检索。

### 6.3 知识域

实体包括：

- `knowledge_card`
- `outline`
- `learning_record`
- `source_reference`
- `export_record`

知识卡片、大纲和学习记录都必须保留来源消息、资料、任务或章节的引用。

### 6.4 资料域

实体包括：

- `asset`
- `document`
- `document_text`
- `asset_link`

原始资料存放于本地资料库。解析文本和 FTS5 索引均为可重建数据。

### 6.5 系统域

实体包括：

- `local_identity`
- `provider_profile`
- `job`
- `approval_request`
- `notification`
- `backup_record`
- `layout_config`
- `layout_template`
- `domain_change_log`

API 密钥不保存在 `provider_profile`，只保存提供方、模型、能力覆盖和配置版本等非敏感信息。

数据规则：

- 所有实体使用稳定 ID。
- 时间按 UTC 保存，界面按用户时区显示。
- 删除保留必要的删除标记，并将资料文件先移入应用回收站。
- 搜索索引、缓存和 AI 中间结果不作为唯一数据源。
- 首阶段不直接同步 SQLite 文件。

## 7. AI Harness 设计

### 7.1 工作流拆分

首阶段按用途建立独立 LangGraph 工作流：

- 计划快速生成。
- 对话式引导规划。
- 学习辅导对话。
- 知识卡片和大纲生成。
- 学习记录生成。
- 计划重排建议。
- 分支摘要。

工作流共享上下文组装、模型调用、结构校验、审批和持久化组件。

### 7.2 标准执行流程

```text
用户请求
  -> 识别工作流
  -> 组装上下文
  -> 用户查看并移除上下文
  -> 调用模型
  -> 校验结构化结果
  -> 生成草稿或变更预览
  -> 用户确认
  -> 领域服务事务写入
  -> 记录模型、来源和执行结果
```

普通聊天无需逐次确认。创建或修改持久化数据必须进入审批节点。

### 7.3 工具权限

只读工具可以自动执行：

- 读取当前任务和计划。
- 搜索资料、历史消息和知识卡片。
- 计算进度和可用学习时间。
- 获取当前分支上下文。

写入工具必须确认：

- 创建或批量修改计划。
- 调整排期和依赖。
- 保存知识卡片、学习记录和对话关联。
- 导出文件。
- 删除或覆盖内容。

首阶段禁止模型执行 Shell、任意 Python、网络爬取或未定义的外部工具。

### 7.4 提供方与回退

支持 OpenAI 及 OpenAI API 兼容服务、Google Gemini 原生接口和 Anthropic Claude 原生接口。

全局模型作为默认兜底，计划生成、辅导、摘要、分支处理和检索嵌入能力可以单独覆盖；单次对话也可以临时切换模型。专用模型不可用时回退到全局模型，必须明确告知用户，不能静默切换。

每次执行记录实际提供方、模型、配置版本、提示词版本、上下文来源、耗时和错误状态。

## 8. 错误处理和数据一致性

- 结构化 AI 输出必须通过 Schema 校验，失败后有限次数修复。
- 网络错误、限流和超时使用有限重试，禁止无限循环。
- 用户取消流式请求后停止后续处理。
- 未确认结果保存为草稿，不修改正式数据。
- 导入资料被视为不可信内容，其中的指令不能覆盖系统规则或直接触发工具。
- 文件先写入临时区，校验哈希后原子移动到资料库。
- 甘特图批量调整、AI 计划写入和依赖修改必须整体提交或整体回滚。
- 后台任务状态使用 `queued/running/succeeded/failed/canceled`。
- 进程异常退出后，可安全重试的任务重新排队。
- FTS5 或缓存损坏时重建，不影响原始数据。
- 数据库完整性检查失败时进入只读恢复模式。
- SSE 断开或浏览器刷新不得重复提交同一 AI 任务。

## 9. 性能目标

### 9.1 本地服务

- 常驻服务目标内存占用控制在 400 MB 内。
- 常规查询、任务更新和本地接口目标 P95 小于 300 ms。
- 在 10 万条消息或资料记录规模下，FTS5 搜索目标 P95 小于 500 ms。
- 资料解析、备份和 AI 工作流采用有限并发。
- 甘特图和分支画布首阶段保证几百个节点可操作，使用折叠、分页和按需加载。
- AI 首 token 时间单独统计，因为它取决于外部模型服务。

### 9.2 远程同步节点

远程同步不进入首阶段，但未来同步节点的约束是：

- 峰值内存不超过 500 MB。
- 只做设备验证、加密增量数据和附件块的存储转发。
- 不运行 AI、计划计算、文件解析、全文索引或业务冲突处理。

## 10. 测试策略

- 领域单元测试：四层计划、依赖类型、循环检测、进度、逾期和重排。
- SQLite 集成测试：事务回滚、迁移、FTS5 重建、备份恢复和任务重试。
- AI 工作流测试：结构化输出、审批取消、模型超时、回退和重复提交。
- 提供方适配器使用 Mock，不在自动化测试中消耗真实 API。
- Playwright 端到端测试：创建计划、甘特图调整、计时、完成任务、创建分支、生成知识卡片、导入资料。
- 安全测试：访问令牌、会话撤销、API 密钥脱敏、日志和备份泄露。
- 桌面与移动视口测试：甘特图、分支画布、底部抽屉和长文本布局。
- 性能测试：大规模任务、消息、资料、画布节点和备份恢复。

## 11. 开发阶段

1. **基础运行阶段**：WSL2 启动脚本、访问令牌、React/FastAPI、SQLite、迁移、备份和基础布局。
2. **学习计划阶段**：四层计划、任务、计时、日历、提醒和基础驾驶舱。
3. **AI 阶段**：三类模型提供方、上下文预览、计划生成、引导式规划和审批流程。
4. **对话阶段**：普通对话、计划关联、分支创建/切换、窄轨和全屏画布。
5. **知识阶段**：资料导入、PDF/Markdown/TXT 解析、FTS5、知识卡片和 Markdown 导出。
6. **排期阶段**：完整甘特图、四类依赖、循环检测和 AI 排期建议。
7. **质量阶段**：端到端测试、性能测试、恢复测试和 WSL2 宿主机访问验证。

P2P、加密同步节点、设备配对、冲突合并、Windows 桌面封装、Android 客户端、Embedding 检索、`.xmind` 输出和资源约束排程均属于后续阶段。

## 12. 验收标准

首阶段完成后，用户应能在 WSL2 启动服务并通过 Windows 浏览器：

1. 创建、编辑和查看四层学习计划。
2. 使用手动、AI 快速生成和 AI 引导三种方式创建计划。
3. 在日历和甘特图中调整任务及依赖。
4. 开始、暂停、继续和结束学习计时。
5. 使用普通 AI 对话，并查看当前任务相关上下文。
6. 从历史消息创建、查看和切换分支。
7. 导入 PDF、Markdown 和 TXT，并进行全文搜索。
8. 生成、编辑、保存知识卡片和 Markdown 大纲。
9. 在 AI 写入正式数据前查看变更并确认。
10. 使用自动快照和手动备份恢复本地数据。
11. 在 AI 服务不可用时继续使用计划、计时、资料和已有内容。

## 13. 设计结论

正式产品名为「学海无涯」，英文名和工程代号统一为 `Nautilus`。首阶段是单设备、本地 WSL2 Web MVP；服务器同步、P2P 和多端封装不参与核心业务运行，也不属于首阶段实现范围。
