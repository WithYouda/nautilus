## 2. 作者本轮已确认的行为

1. 在分步教学中要求“直接给答案”或“完整讲解”，默认仅改变本轮；下一轮恢复原方式。明确说“以后都这样”才持续，不自动覆盖长期个人默认模式。
2. 回答只输出部分便取消或中断，步骤回到生成前的位置，不自动推进；部分回答和既有帮助记录保留，不假称本轮未提供过任何帮助。
3. AI可从实际消息中识别一次尝试并关联当前步骤，但须标为AI识别，允许用户纠正。保留原文与当时版本；识别、纠正和尝试次数都不能成为完成、通过验证或掌握的证明。

继续沿用已确认边界：教学模式切换发生在安全回合边界；用户可以直接要求完整解释，不强制逐级点击。临时步骤不直接写正式计划，教学不重评分、不写完成事实或掌握结论。工具/资料授权与教学方式、Provider选择独立。

## 3. 建议的最小状态与归属

以下是工程方案，**不是当前已有的教学状态实现，也不将方案整体记录为作者已批准的产品决定**。优先复用现有JSON及版本关系；具体字段在实施时定型，不建设通用协议平台。

| 需要保存的状态 | 建议归属与含义 |
| --- | --- |
| 协议与教学方式 | 对应回答的运行记录内保存协议ID/版本、本路径的基础方式、本轮实际方式、请求来源与持续范围。首片使用既有默认分步教学；其他模式的完整实现归C2。 |
| 生成前检查点 | `ai_run.config_snapshot_json`或`learning_discussion_turn.provider_snapshot_json`内的教学快照。包含明确步骤引用及当前允许动作；步骤未知时保留未知，不从旧正文或位置概括回填。 |
| 当前小点 | 临时教学步骤身份、简短内容与提出它的具体回答引用；教学步骤不是正式任务，不带通过、完成或掌握字段。 |
| 实际尝试 | 引用具体用户消息/问题版本或原作答，不复制正文。AI识别作为可纠正观察保存，纠正追加修订，不能覆盖原文。普通消息默认不是尝试。 |
| 已提供帮助与提示等级 | 引用现有回答/展示记录。分别保存协议允许的帮助层级与可追溯的实际输出；历史或无法确定的实际层级为未知。首片不补造H0–H4等级或自动升级次数。 |
| 运行后检查点 | 只在输出完整、结构校验和运行持久化成功后采用合法步骤变更；提案未采纳、空输出、取消、失败或中断不能推进步骤。保留生成前快照和部分帮助事实。 |
| 工具、资料、模型 | 引用同一运行已有的`source_scope`、搜索/知识库授权及模型快照，不复制正文或再建授权表。更换教学方式不扩权；授权撤销/清除仍使用现有执行前校验。 |
| 当前界面位置 | 由现有服务端所选回答路径决定。位置概括仍是独立可修订注释，不升级为教学执行检查点。 |

教学状态需要驱动后续执行和恢复；单独保存模型自报的“当前步骤”而不校验、不消费，不能算有状态教学完成。尝试识别、步骤提案及自然语言方式识别可使用同一次教学调用的结构化结果；应先核对四协议与所用模型的实际能力，不能未经说明强迫所有模型支持新的函数工具，也不为了记状态默认增加第二次模型调用。

## 4. 版本、分支与恢复规则

- **普通续问：** 从所选父回答的合法检查点继续，接受本轮明确请求后冻结执行条件。用户输入先按现有链保存；模型失败不丢失输入，不伪造尝试识别。
- **临时方式覆盖：** 本轮实际方式与恢复方式分别记录。下一轮恢复路径的基础方式；明确的持续请求只能改变本路径后续方式，不改其他对话、旧回答或长期个人默认。
- **重新生成：** 从原问题之前的检查点重新执行，不继承被替换回答的步骤推进或后续尝试。沿用原问题身份，新回答有独立运行快照；新运行采用明确选定的当前执行参数，已接受请求的幂等重放仍返回原运行。
- **编辑问题：** 创建原位置的问题新版本，从原问题之前的检查点开始；保留旧问题、旧回答及各自后续状态，不覆盖底部草稿。
- **切换回答版本：** 恢复该版本及其后续路径的教学检查点，不能把较新版本的步骤、尝试识别或提示等级混入旧版。
- **独立分支：** 仅继承分出回答及其祖先的检查点，映射本地消息引用，保留原来源；后续独立推进。继承的原帮助/尝试观察不是第二次发生，不重复计数。
- **刷新或断流：** 重读服务端运行/路径，继续订阅原运行；不从浏览器缓存猜步骤或重发模型请求。
- **取消、失败与服务中断：** 步骤恢复生成前的位置，部分输出继续可看；“输出过什么”与“教学推进到哪里”分开。重新生成是新运行，不复用已失效的工具许可。
- **来源失效或清除：** 跟随现有对象/资料清除、分支依赖、备份与恢复屏障；不得让教学字段成为恢复已删除正文的副本。失效路径要求用户明确重新选择，不扩大资料范围。
- **纠正尝试识别：** 追加可追溯修订供之后执行使用，不改历史输入、历史运行快照或已冻结正式作答的帮助条件。

## 5. 建议的第一个可用切片

围绕现有分步教学完成一段“讲一个小点 → 用户回应/尝试 → 继续或请求帮助 → 中断 → 恢复”的真实流程。同步覆盖普通学习室与题目讨论的共用状态边界，不一次实现C2六种模式、自动H阶梯或C3模型策略层级。

- **运行时：** 一个窄的教学契约/校验组件，两处对话接入生成前冻结与成功/失败收敛；尝试识别与用户纠正有明确来源。复用当前运行、消息和帮助事实，不另建会话/帮助账。
- **版本及治理：** 两处分支映射新增引用；清除/受管理备份/恢复检查覆盖新增状态。优先用已有JSON保存；若确有关系查询或并发写入需求才提出新增结构，并用正式工具演练。
- **界面：** 沿用折叠学习安排与帮助记录入口，显示实际当前小点和必要下一动作；尝试的AI识别可查看/纠正，未知留空。只显示日常语言，不展示内部协议字段、H枚举或状态调试表。具体呈现随实现核对，不先重构全站。
- **预期文件：** `conversations.py`、`question_discussion.py`、`ai_runtime.py`及一个共用教学契约模块；两处分支和清除边界按实际新增引用接入；`AiLearningRoom.tsx`、`QuestionDiscussion.tsx`、`api.ts`与必要的共用呈现。现有`HelpRecord`观测语义及`verification_help.py`的正式作答快照不改造成重复教学记录。

必要验收：一个步骤和一次真实原文尝试可追溯；普通提问不误计、AI识别可纠正；临时/持续方式分别恢复；重生成/编辑/切换旧版本/独立分支不串状态；取消部分输出、空失败、刷新和进程中断均不自动推进；旧页面修订冲突不覆盖且不重发；模型/资料/联网变化不改历史快照，工具仍按原授权执行；原计划、提交、评估、完成与成果状态不被教学改写。沿用未变检查，只补改变的流程及重要数据边界。

## 6. 本轮已实施与下一项

已实施：题目讨论在接受turn时保存实际非秘密模型配置，配置不再依赖历史选择调用成功才留存；运行中修改设置不改变本轮，重新生成保存新配置，重放/分支/清除沿用既有记录。旧回答缺少的配置不按当前设置补造。无结构迁移或前端改动。

下一项：把本契约的最小检查点、步骤/尝试引用、方式持续范围和中断回退接入第一个分步教学流程，先核对单次调用的结构化状态回传方式及模型兼容性，再实现和验收。该回传方式属于尚未定型的工程方案；协议可靠执行前，不宣称C1有状态教学切片已完成，也不提前扩展C2/C3。
