## 1. 目标与边界

本轮改进 AI 学习室的高频输入、回答阅读和 OpenAI 兼容提供方设置体验：

- 输入框普通 `Enter` 发送，`Shift+Enter` 换行；输入法组合期间不误发送。
- AI 正文按 GFM Markdown 渲染，而不是按纯文本展示。
- 模型字段可从 Base URL 自动发现模型、缓存结果并允许手动填写。
- 连接测试前可从发现结果中选择测试模型，测试成功状态清晰可见。
- 只展示 provider 实际返回的推理内容；生成中展开，结束后默认折叠。
- 收敛学习室头部、上下文和输入区高度，让回答区在浏览器 100% 缩放下占据主要空间。

不展示、推断或伪造模型未通过 API 返回的隐藏思维链。不调用真实 AI API完成自动化测试，不记录真实凭据或用户内容。

## 2. 输入与 Markdown

学习室输入框在未按修饰键、非输入法组合且消息可发送时，`Enter` 阻止默认换行并提交当前表单；`Shift+Enter` 保留原生换行。`Ctrl/Meta/Alt+Enter` 不作为发送快捷键，避免与浏览器或辅助工具冲突。

助手消息使用 GFM Markdown 渲染，支持标题、段落、强调、列表、任务列表、引用、链接、表格、行内代码和围栏代码块。用户消息继续按纯文本展示，避免把用户原始输入误解释为富文本。链接使用安全协议并在新标签页打开；不启用原始 HTML 解析。

## 3. 模型发现与缓存

新增后端接口：

```text
POST /api/ai/provider/models
```

请求携带当前表单中的 Base URL，以及可选的临时 API key。临时 API key 只存在于请求内存，不写数据库、日志或缓存；未提供临时密钥时使用当前保存密钥。后端校验 Base URL 后请求 OpenAI 兼容的 `/models`，兼容 `{"data":[{"id":"..."}]}` 和可识别的模型字符串列表，去重、排序并限制返回数量与响应体大小。

缓存保存在后端进程内存，键由本地身份、标准化 Base URL 和不可逆凭据指纹组成，不保存 API key。成功结果缓存 10 分钟；相同键在有效期内不重复出站。前端打开同一设置对话框时也复用最近结果。用户可显式刷新模型列表；Base URL 或 API key 改变后使用新的缓存键。

模型字段采用可编辑组合框：聚焦时触发缓存优先的发现流程；成功时显示下拉列表并可选择，失败或返回空列表时仍允许手动填写模型名称。网络错误不会清空已有模型值。

## 4. 连接测试

点击“连接测试”后先打开模型选择弹窗。候选项来自当前缓存/发现结果，并包含当前手动填写模型；用户也可在弹窗中输入其他模型。确认后，后端使用当前表单配置直接测试所选模型，因此首次配置无需先保存才能测试。

新增接口：

```text
POST /api/ai/provider/test
```

请求可携带临时 Base URL、模型、API key 和超时；缺失项才回退到已保存配置。测试不会隐式保存提供方配置。成功后在“连接测试”按钮右侧垂直居中显示绿色状态，包含模型和延迟；模型组合框中测试成功的模型旁显示绿色圆形勾。测试失败保留弹窗选择和表单内容，并显示脱敏错误。

## 5. 可见推理内容

OpenAI 兼容流解析以下 provider 明确返回的字段：

- `delta.reasoning_content`
- `delta.reasoning`
- 正文流中的 `<think>...</think>` 块

适配器将流规范化为 `reasoning` 与 `content` 两类增量。推理内容不混入最终正文。为支持断线恢复和历史查看，新增 `006_ai_message_reasoning.sql`，为 `message` 增加 `reasoning_content TEXT NOT NULL DEFAULT ''`。虽然默认数据库尚未应用 `005`，隔离手测库已经应用过它，因此不能依靠原地修改 `005` 升级现有隔离数据；`001–005` 保持不变，本轮也不把 `005/006` 应用到默认数据库。

SSE 的 `start`、`done` 和 `error` 带完整 `reasoning_content`，增量事件区分正文和推理。生成中推理区域以低对比灰褐色默认展开；运行结束后自动折叠为“已思考，点击展开”。无推理内容时不渲染该区域。推理区域按纯文本展示，不执行 Markdown 或 HTML。

## 6. 学习室密度与响应式

学习室保持当前铺满结构，但将头部改为紧凑工具栏：标题使用响应式字号，副标题限制为单行省略；上下文折叠栏降低最小高度；输入框默认约两行并限制手动扩张上限。对话面板使用 `minmax(0, 1fr)` 占据剩余高度，消息列表是主要滚动容器。

桌面、窄桌面和移动端分别校准间距。浏览器 100% 缩放时，桌面视口中回答区域必须明显高于头部、上下文和输入区总和；移动端保持输入和发送操作可见，不产生页面级横向或纵向溢出。

## 7. 验收与测试

- 组件/浏览器测试验证 `Enter` 发送、`Shift+Enter` 换行和输入法组合不发送。
- Mock provider 返回 GFM 正文，浏览器验证标题、列表、表格和代码块形成语义节点，原始 HTML 不执行。
- 后端测试验证模型发现解析、缓存命中、缓存键隔离、错误脱敏和临时配置测试。
- 浏览器测试验证模型下拉、手动输入、测试选择弹窗、按钮右侧绿色成功状态和模型绿色圆形勾。
- Mock provider 返回显式推理增量，验证生成中展开、完成后折叠、刷新后恢复。
- 生产 preview 截图检查 `1440px`、`1024px` 和 `390px`，并核对浏览器 100% 缩放下回答区占比。
- 运行后端全量测试、前端生产构建、Playwright 全量测试、脚本安全测试和 `git diff --check`。

## 8. 数据安全

- 不把 API key 写入 SQLite、模型缓存、日志、文档、URL、localStorage 或 sessionStorage。
- 模型缓存仅保存模型名称、时间和不可逆凭据指纹。
- 不读取或记录 CLI Proxy API Management Center 的本地凭据；只参考其可编辑模型与模型列表交互思路。
- 本轮新增 `006_ai_message_reasoning.sql`，不修改 `001–005`；默认数据库保持不变。
