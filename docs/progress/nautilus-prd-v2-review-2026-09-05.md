## 1. 审查结论

PRD V2 的产品定位、双轴模型、证据原则、统一 Agent Runtime 和混合事件账本方向已经能够作为后续规格的基础。但首个纵切片仍有若干会导致返工或语义漂移的问题，不建议直接据此编码。

本记录保存原始审查发现、建议和后续处理结果；只有明确标记为已确认或已按既有决策落实的处理结果才视为关闭，原始建议不自动成为产品决策。P0、P1 和本轮 P2 已处理；下一项是用户复核修订后的 PRD，再进入领域/架构规格建议。

## 2. P0：进入工程规格前必须处理

### P0-1：首个纵切片没有规定达成标准的来源

依据：PRD V2 第 11.2 节要求创建可验证成果、生成证据主张并派生学习状态，但没有规定达成标准版本由谁提供、来源是什么、是否经过确认。

风险：没有可追溯标准，Core 无法判断“依据不足”和“初步支持”；Agent 可能自行编造学习标准，违反陌生领域来源边界。

建议：首个纵切片只允许使用预先固定的窄领域标准，或用户明确提供且可追溯的标准。标准必须包含来源、版本、能力维度、帮助条件和最低证据组合。没有合格标准时，只保存原始产出，不派生学习状态。

处理结果（2026-09-05，已确认）：首片只有预先审核并版本化的窄领域标准包可以参与状态派生；用户提供的可追溯标准先作为候选来源保存，未纳入标准包前不得参与状态派生。没有合格标准时仍可保存会话、原始产出和事实事件，但不生成证据主张或学习状态，并记录标准缺失原因。该规则已写入 PRD V2 第 11.2.1 节。

### P0-2：首个纵切片范围过大，缺少工程切口

依据：当前范围同时包含委托、契约、成果、会话、产出、事件、AI 证据、状态派生、复核、撤销和回放。

风险：一次跨越多个新领域，容易形成对象和接口都存在、但没有一个完整流程可靠可用的纵切片。

建议拆成连续两个验收门：

1. 事实闭环：委托、标准、会话、文本产出、事件、关系型投影和回放；
2. 证据闭环：候选主张、状态派生、质疑、复核和撤销。

第一阶段使用固定标准和确定性样例验证 Core，第二阶段再接入 AI 语义主张。

处理结果（2026-09-05，已确认）：首片拆为两个连续验收门。事实闭环门先验证委托、标准绑定、会话、文本产出、事实事件、关系型当前态投影和回放；证据闭环门必须在事实闭环通过后，再验证候选主张、状态派生、复核、质疑、撤销和证据回放。该拆分已写入 PRD V2 第 11.1、11.4 和 12.2 节。

### P0-3：没有定义 AI 不可用、超时或输出不合格时的行为

依据：PRD V2 将 Agent 生成证据主张写成正常路径，但没有失败路径。

风险：外部模型失败会阻塞用户保存学习产出，或产生空主张、伪造状态和重复运行。

建议明确：原始产出和学习会话始终可以保存；AI 失败只记录待分析或失败事件；不得生成空主张或状态；重试必须幂等；用户可以手动请求复核。

处理结果（2026-09-05，已确认）：学习会话和原始产出独立于 AI 保存；AI 超时、不可用、取消或输出不合格时只记录分析失败，不生成空主张、伪造主张或学习状态，且失败不等同于“依据不足”。用户可以重试、请求人工复核或安排补充验证；重试不得重复产生事实或重复计入同一批证据，失败与成功运行均可审计。没有合格标准时不启动状态分析。该规则已写入 PRD V2 第 8.3、11.2.2 和 11.4.2 节。

### P0-4：新领域模型与旧任务入口的切换边界不清楚

依据：PRD V2 一方面要求选择“现有学习行动”，另一方面要求连接现有任务/计划入口，同时声明旧固定层级不构成兼容约束。

风险：工程实现会在新模型和旧 `learning_goal/subject/topic/task` 之间形成未定义的兼容层，污染新领域语义；或者误把旧任务数据直接当成新事实。

建议在工程规格中明确首片的切换边界。推荐首片先使用新领域模型独立验证，旧数据保留并只读，不让旧层级语义进入新 Core；后续再单独制定用户数据迁移和恢复方案。

处理结果（2026-09-05，已确认）：首片直接使用新领域模型独立验证；旧 `learning_goal / subject / topic / task` 固定模型、旧任务/计划入口、旧数据语义及其兼容映射、双写和适配层均不进入首片，也不构成未来兼容要求。用户历史数据保护通过备份、校验、恢复和授权规则处理，不通过兼容层延续旧模型。该规则已写入 PRD V2 第 8.2、11.2、11.3 和 12.2 节。

### P0-5：事件账本要求不足以支撑“回放可用”

依据：PRD V2 确认混合事件账本，并把状态、审查动作和撤销从事件与投影重建列为验收条件，但没有定义事件唯一标识、顺序、幂等键、投影版本和重建失败处理。

风险：不同实现者会对“事件是事实”“投影可重建”作出不同解释，导致审计、撤销和状态重算不可验证。

建议在架构规格中至少明确：命令重试不能产生重复事实；事件追加和当前态投影在同一事务内完成；投影可删除后从事件重建；派生状态不能成为原始事实；事件版本变化必须有升级策略。

处理结果（2026-09-05，已确认）：首片事件账本增加最小回放不变量：事件全局唯一、聚合内顺序单调、命令幂等键、事件与投影同事务提交、投影位置和顺序缺口处理、隔离位置重建与校验后原子切换、重建失败保留现有投影并审计、派生状态不得成为事实源，以及事件版本显式升级或拒绝重建。回放还必须校验事件数量、顺序、投影版本和关键领域约束。该规则已写入 PRD V2 第 9.1、11.4.1 和 11.4.2 节。

## 3. P1：应在 PRD 或首片规格中补齐

### P1-1：原始产出与事实事件被合并描述

原审查发现：PRD V2 的主要对象表把二者写成“原始产出/事实事件”。建议拆开：原始产出是不可篡改的内容，事实事件记录何时、由谁、通过什么动作产生该产出，证据主张同时引用产出和事件。

处理结果（2026-09-05，已确认）：PRD V2 第 5.2、6.2、8.3、11.4.1 和 11.4.2 节明确两个独立对象；首片候选主张同时引用文本产出及对应事实事件，事实闭环保存内容和产生时间、主体、会话及动作。具体字段、表结构和 API 留待工程规格。P1-1 从待处理项移除。

### P1-2：“用户可以接受处理”语义不准确

原审查发现：该表述容易被理解成用户点击认可后，主张就自动升级为稳定证据。建议改为“查看依据、采纳符合条件的主张、提出质疑、暂不处理或安排验证”，并明确用户采纳不等于成果状态升级。

处理结果（2026-09-05，既有决策落实）：产品决策记录第 52、53、56 条已经覆盖审查生命周期与状态贡献分离、保守采纳和复核交互。本轮校正 PRD V2 第 6.4、8.3、11.2 和 11.4.2 节中的动作描述，并明确采纳不直接升级成果状态。P1-2 从待处理项移除，不新增产品决策。

### P1-3：缺少事实纠正和隐私删除流程

PRD 同时要求原始产出不可篡改、支持删除标记和可恢复，但没有说明用户发现原始记录错误时如何处理，也没有说明隐私删除后相关证据主张和派生状态如何重算。

建议采用更正事件或新版本表达事实纠正；隐私删除使用删除/脱敏事件，并定义证据失效、状态重算和审计元数据保留规则。

处理结果（2026-09-05，已确认）：事实纠正追加更正事件或新版本，不覆盖原始产出；依赖被更正事实的证据主张保留历史但移出当前状态计算，相关成果状态和回访队列由 Core 重算。用户-facing 名称采用“彻底删除”：它清除或不可逆脱敏内容，依赖内容的主张立即失效；缓存、索引和普通备份不得恢复删除内容，只保留不含私人内容的最小审计元数据。删除前须说明受影响范围，删除后不得伪造新的学习事实。普通删除和撤回的可恢复语义另在 P2-3 补充。该规则已写入 PRD V2 第 3.4、9.2 和 11.4.2 节。P1-3 从待处理项移除。

### P1-4：首片验收没有覆盖权限和用户体验

原审查发现：验收主要验证后端数据。应补充：全局 Agent 默认看不到原始文本；权限申请说明目的、范围和时效；复核卡显示权限限制；用户拒绝权限后仍可继续；AI 失败时仍可保存产出。

处理结果（2026-09-05，已确认）：沿用产品决策记录第 54、56、64 条，将既有权限与 AI 失败规则落实为首片验收。事实门覆盖跨身份及同一用户内部范围隔离、拒绝越权读取和未授权写入、未启用 AI 时保存并重新打开产出；证据门覆盖全局最小上下文、主动申请的五项说明、授权结果与过期/撤销审计、拒绝后继续保存、复核卡可见范围，以及 AI 失败时的保存结果、失败原因和恢复入口。用户自行查看产出不等于授权 Agent 读取。已写入 PRD V2 第 7.4、10、11.4.1 和 11.4.2 节，P1-4 从待处理项移除；权限原则本身不重新讨论。

### P1-5：缺少产品成功指标

当前有功能验收，但没有判断长期学习协作者是否真的产生价值。建议定义测量对象和护栏，例如：中断后恢复到正确委托的比例、证据主张可追溯比例、无依据主张率、用户质疑率、复核到下一行动的完成率、模型不可用时产出保存成功率、事件重建一致性。

这些指标暂时不必设定最终目标值，但应明确如何测量。

处理结果（2026-09-05，已确认）：首片采用测量契约，先定义测量对象、分母、观察窗口、排除条件、来源事件和隐私保留边界，建立真实使用基线后再设业务目标值。产品价值指标为中断后正确恢复委托比例、复核到下一行动完成率和证据可追溯率；无依据主张率、指定 AI 故障场景的产出保存成功率、事件重建一致性、权限违规和隐私泄露为硬性护栏；用户质疑率、暂不处理率、无合格标准时的降级比例、分析失败重试率和人工复核请求率只作诊断。主动切换委托、权限不足、等待验证、零分母和窗口未满均需单列，不能美化完成率。任一硬性护栏未通过，都不能宣称首片成功。该规则已写入 PRD V2 第 11.5 节，P1-5 从待处理项移除；具体字段、窗口、报表和采样实现留待工程规格。

### P1-6：终局需求和首片需求没有显式优先级标记

PRD 同时描述终局能力和首个纵切片，工程人员可能误把目标、路径图、成果图、主动教练等终局需求当作本轮必须完成的功能。

建议在需求条目中显式标记“终局不变量”“首片必须”“后续规格”“明确暂缓”，并给首片需求增加稳定编号。

处理结果（2026-09-05，已确认）：需求性质与交付范围分开标记。性质区分跨阶段不变量和具体功能；范围区分事实门、证据门、后续和暂缓，两种标记可以同时适用。不变量不能因为标记为跨阶段就被推迟到首片之后；终局功能也不能因为写在正文中就自动进入首片。“待工程规格分解”只表示准备状态，不是优先级。首片需求增加稳定编号，并关联正文依据、验收门和验收条件；后续工程规格与测试引用编号而非易变章节位置。该规则已写入 PRD V2 第 11.6 节，P1-6 从待处理项移除。

原建议（2026-09-05，已按上述确认结果落实）：

- 将约束性质与交付范围分开标记：约束性质区分跨阶段不变量和功能需求；交付范围区分首片验收门一、门二、后续规划和明确暂缓，两门可同时适用。权限等不变量需要在首片落实，不能把“不变量”误解为远期需求。
- “待工程规格分解”属于规格准备状态，不能代替交付范围；首片必须项也仍需工程规格。
- 首片增加稳定编号的需求清单，每项关联正文依据、所属验收门和验收条件；工程规格与测试引用这些编号，不再依赖容易变化的段落序号。
- 依据已确认的第 11、13 节标记现有范围，不重新扩张首片。完整路径图、成果图和主动后台教练归后续规划，云同步和社区市场等保持明确暂缓；首片保留已有闭环所需的最小入口和权限流程。
- 不变量仍约束所有阶段；交付范围以首片清单为准，终局正文中出现某项能力不等于本轮必须实现。若分类暴露新的范围冲突，单独说明再确认。

## 4. P2：应在下一版文档中澄清

- “目标”“综合成果”“可验证成果”已经区分，但首片没有写清三者如何关联；应明确首片允许的最小关联链。
- 原产出修改、追加版本和删除问题：更正追加新版本、隐私删除及证据失效已由 P1-3 确认，不再讨论；仍需明确“撤回产出”是否独立于更正和隐私删除存在，以及对证据适用性的影响。具体事件命名属于后续工程规格。

已去重关闭（2026-09-05）：原 P2“跨身份及同一用户内部 global/plan/task 隐私范围验收”已并入 P1-4，并写入首片两门验收，不再作为待处理问题；这里的范围语义不要求兼容旧模型或旧入口。

已去重关闭（2026-09-05）：原 P2“任务/学习行动命名”由产品决策记录第 14.12 节和第 34 条覆盖。任务的领域语义是可执行学习行动，界面可继续称“任务”，不另建一个学习行动实体；PRD V2 第 5.2 节已同步说明。具体代码、API 和事件名称留待工程规格，不把命名再次包装成产品方向问题。

处理结果（2026-09-05，已确认）：首片不强制创建综合成果，围绕一项可验证成果及其合格标准版本完成任务、委托、会话、产出和证据闭环；综合成果留作终局组织层，后续关联不复制或重置证据；无合格标准继续走保存降级。该规则已写入 PRD V2 第 11.2.3 节，P2-2 关闭。

### P2-3：产出撤回、普通删除与彻底删除边界

处理结果（2026-09-05，已确认）：普通删除是正常可用、可恢复的软删除；撤回只改变证据适用性，保留原始内容并允许明确恢复；“彻底删除”是不可逆的内容清除，依赖主张立即失效，删除前展示影响并要求确认。事实纠正追加新版本，不原地修改。具体事件、回收范围、恢复组件属于工程规格，P2-3 关闭。

已去重关闭（2026-09-05）：P1-3 已覆盖事实纠正、版本追加和彻底删除后的证据失效；本项只补充普通删除与撤回的正常用户操作边界，不重新定义 P1-3 的隐私保护原则。

- 目标不强制预先建立、计划可直接拥有任务、成果与任务语义分离，均为既有结论，不再询问。
- 本项仅建议首片不强制创建综合成果：围绕一项可验证成果及其合格标准版本，完成任务、委托、会话、产出和证据链的验证，不为凑齐层级自动创建空综合成果。
- 综合成果仍是终局模型的一部分；以后需要整体能力组织时，再关联已有可验证成果，保留成果身份和原有证据引用，不复制或重置历史。
- 无合格标准时继续沿用既定保存降级规则。本项不决定首个领域，也不更改证据门槛或引入完整成果图。
