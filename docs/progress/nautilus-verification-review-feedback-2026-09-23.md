## 已核对事实

| 反馈 | 当前实现与缺口 |
| --- | --- |
| 提交后本人答案消失 | `LearningVerification.tsx` 仅 answering 时渲染输入框；`verification.py:_public` 不提供提交正文。`_submit` 在模型调用前保存不可变提交并链接原始产出，`verification_content.py:submission_content` 可从原始产出读取。本人回看没有独立读取/展示链。未查询真实记录，不能证明某条实际提交的存储状态。 |
| AI 提出更多问题却无法回答 | 评估契约只有整次 passed/stop_condition_met/feedback/next_step，未结构化为逐题反馈/拓展问题。确认后禁止改写完成的验证，也没有关联题目的续问入口。不能用“重新提交”覆盖历史结果替代讨论。 |
| 题目/作答/AI 答案保存与错题回看 | challenge、服务端 answer_key、提交和评估均有存储路径；界面缺少可发现的历史详情，AI 参考解法没有面向用户的独立展示契约。需要自动保存状态与本人历史入口，而非额外让用户重复保存才不丢。旧整次反馈不能事后伪装成原始逐题结果。 |
| 彻底删除按钮用途 | `_purge` 清除该验证题目/评估依据/所有提交/评估正文，并经产出清除链使依赖证据失效；已有完成事实保留。页面用普通安静按钮直接排列在表单尾部，虽然点击后确认，但日常层级不合理。该能力是隐私控制，不是学习结束步骤。 |
| 完成后找不到委托 | 确认完成变更状态，不删除委托。state 返回委托；高级工具可选择记录，但常用返回卡只突出当前/开放任务，没有完整已完成委托历史与验证详情入口。新领域与旧计划页面分离进一步造成误解。 |
| 右侧 AI 学习伙伴用途 | 08-01 历史设计为规划时短对话、长对话进入学习室；08-04 规格区分全局/计划/任务范围。当前 `AiCompanionPanel.tsx` 仅以旧计划/今日摘要展示上下文、配置和学习室跳转，不是已经运行的后台教练，也未接入新委托闭环。 |

## 最小实施建议

统一为“学习记录 → 委托 → 验证详情 → 单题继续学习”，补强已有对象，不开发独立题库平台。

- 本人鉴权详情展示题目、提交版本、当次作答、对应 AI 反馈；参考解法明确模型来源，不展示隐藏评分/内部推理。全局列表和未授权 Agent 不获得正文。未提交不提前揭示解法；看过提示再答不能自动认定独立表现。
- 从某题建立关联的新对话，初始引用该题、作答、反馈与委托范围。`LearningRoomService` 已有同委托对话列表和归属校验，可复用；`ConversationService.prepare_run` 只加载当前 conversation 的历史，**尚无实际跨会话检索**，不能以一句提示词宣称实现。检索应允许在本人同委托记录内按需找内容、引用来源、遵守可见性和权限限制，不默认拷贝全部历史。
- 本次结果、后续讨论、新练习分别保存；完成状态不被可选拓展撤销。若缺失的是原停止条件要求，必须处理通过判断与反馈不一致的问题，不以“通过但继续学”掩盖。
- 删除能力建议下沉至“更多/隐私管理”，保留影响说明和确认；右栏建议默认收起并保留按需规划入口。两者仍是建议，没有替用户决定永久移除。
- 新增任何对话引用/摘录、上下文快照或衍生回答前，明确跨主库/学习库的清除责任及迟到输出处理，防止从验证删除转为聊天副本泄漏。现有删除代码不能被声称覆盖尚未实现的新副本、外部 Provider 或用户导出。
